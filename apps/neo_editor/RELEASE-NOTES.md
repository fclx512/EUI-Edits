# EUI-Edits @NEO_EDITOR_VERSION@ — 发布说明

**EUI-Edits 0.1.4 版本说明。**

## 相比 0.1.3 的主要更新

- **文本模型与内存：** 将稀有的行呈现、详细光标和装饰数据移到按需写前分离的记录；共享相同值的样式记录，源码装饰只保存行长度和相对 token，不再长期保存源码正文副本；进一步压缩纯文本行冷数据，并移除多行布局对光标数组的重复持有。当前候选 README 四场景后台测量中，9 MiB 纯文本专用工作集为 87.8 MiB，9 MiB Markdown 为 186.2 MiB；这些是指定机器和夹具下的闲置值，不是固定上限或交互峰值。
- **文档库响应：** 选择目录、切换库根和返回上级目录统一使用后台扫描；Windows 普通文件复用目录枚举得到的类型信息，减少重复属性查询，同时保留目录联接点、符号链接和文件安全检查边界。
- **稳定性与回归覆盖：** 保留精确源字节范围、换行、宽高、光标和样式语义；扩展源码装饰、统一装饰页、输入回调、文档库异步编辑/保存/撤销、删除与外部回写冲突等测试。
- **发布与诊断：** 统一 `prepare-neoeditor-release.ps1` 发版入口，增加版本/路径/锁/源码漂移保护、独立打包证据和失败日志；新增后台 README 内存、输入容量与目录扫描探针，CI 上传发版证据。

## 验收边界

本版本说明中的内存数据绑定当前候选 EXE 和后台可见窗口测量；组件 CPU 结果不代表完整应用响应或输入到屏幕时延。真实编辑、保存、IME、多屏 DPI、低配设备、持续拖选、硬件 GPU 与设备丢失恢复仍需分别验收；出现未覆盖项时不作普遍性能保证。

更新方法：直接删除旧版本，然后在新版本中的文件关联点击应用并修复即可（如果此前已注册打开方式）。发布前的候选冻结、门禁、打包和验收顺序见[发版流程](../../docs/发版流程.md)。发布说明不附哈希文件表；最终资产哈希由维护者单独核验。
