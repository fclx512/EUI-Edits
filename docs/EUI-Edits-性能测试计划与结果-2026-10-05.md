## 3. 样本制作与清单

样本生成耗时不计入程序启动、目录扫描或打开时间。样本准备后统计文件/目录数、正文 UTF-8 字节数、Unicode 字符数、物理行数、最长物理行、SHA256；换行后的视觉行数只能从实际布局/可验证界面另记。所有文件放在 `fixtures` 内，保存或编辑在它们的运行副本上进行。

| 样本 ID | 内容 / 规模 | 用途 |
| --- | --- | --- |
| J20/J80/J320 | 合法 JSON，目标约 2万/8万/32万字符，短字段组成的数组，UTF-8，无 BOM | 判断文档大小与选区大小影响；实际计数为准 |
| JP20/JP80/JP320 | 格式化多行 JSON，目标同上；标明与压缩版语义相同还是仅规模相近 | 区分长物理行与很多短行；同对象两种格式字节数不同，不当等字节对照 |
| U80 | 约8万字符混合中文、ASCII、emoji 的合法 JSON | UTF-8 字节与字符差异、选区/复制正确性 |
| T80 | 约8万字符纯文本，分成普通短行 | 去掉 JSON 高亮的对照 |
| T1/T9 | 1 MiB / 9 MiB ASCII 纯文本，每物理行128字节，末尾 LF | 与已有 9 MiB 内存记录对齐 |
| TL1/TL9 | 1 MiB / 9 MiB 单物理行纯文本 | 隔离长行与软换行，按小规模到大规模执行 |
| M1/M9 | 1 MiB / 9 MiB Markdown，短行含列表、强调和行内代码 | 与纯文本比较结构成本 |
| MT | 约1 MiB Markdown，含多段表格及少量长单元格 | 表格保留完整度量、列宽与编辑回退 |
| B255/B257 | 约255 KiB / 257 KiB、结构相同的文本 | 检查 viewport metrics 的256 KiB门槛附近行为，不把门槛内外差异归为文件格式 |
| D1/D10/D50 | 1千/1万/5万个小文件，约每100个一目录，包含深度链和 Unicode 名 | 大目录分级基线；正文仅少量字节 |
| DW10 | 1万个同级小文件 | 区分排序/展平/首层展示与递归成本 |
| DS | 小树，含隐藏文件、无扩展名文件、空目录、只读文件 | 文件库正确性 |
| DL/DN | 目录链接或联接点；网络/可移除盘目录 | 有真实环境才测，缺失记 SKIP，不修改系统制造环境 |

JSON 可用 Python 标准库 `json.dumps` 生成固定内容，调数组项数使规模接近目标，再将实际计数写清单。J80 必须在8万字符附近，不能用“8万字节文件”替代用户反馈。建议另从已脱敏的真实样本复现；没有该样本不阻塞生成样本测试，也不称完全复现用户文件。

T9 的精确做法：一行是 `Text row: ` 加117个 `a` 和一个 LF，共128字节，重复73,728次得到9,437,184字节；T1重复8,192次。M9 可参考现有 [readme_memory.py](../tests/probes/readme_memory.py) 的构造，但运行前检查脚本是否会自动启动应用，不为取样本顺带运行整套探针。

目录文件名使用可预测序号，内容可为空或极短；加入固定标记文件 `CURRENT.md` 和若干跨层文件。将所有目录的预期文件名保存为清单，用来校验搜索与刷新。D50准备与单项执行若过慢，先跑D1/D10，保留超时，不无限等待。更大如10万文件只作扩展项。

## 4. 测量方法和停止条件

每个主性能场景至少3次有效独立运行，报告各次原始值和中位数；波动大或前台失效时保留失败轮，再补轮，不删除异常数据。冷/暖要单独命名：本计划的“进程冷启动”是新进程/新配置，不表示清空 Windows 文件缓存；禁止强制清系统缓存或 trim working set。操作系统冷缓存未控制时如实注明。

### 指标

| 指标 | 方法与口径 |
| --- | --- |
| CPU | 目标 PID 的内核+用户 CPU 时间增量除以墙钟时间；明确“100%=一个逻辑核”，若按全机核数归一化另列。采样建议100ms；记录逻辑核数，不直接比较任务管理器百分比 |
| 输入与帧时延 | 输入发送/收到、compose、布局、呈现各阶段已有打点尽量对应；没有可靠关联时只报观察/截图变化的时间，不将屏幕轮询误差当真实输入耗时 |
| 启动 | 分别记创建进程、主窗口首次可见、窗口首次能接受输入、首篇文档可用、首批目录行和目录完成。窗口可见不等于可交互 |
| 内存 | 目标 PID 的整体工作集、专用工作集、专用提交量，均为MiB；建议100ms采集交互峰值，另按旧口径静置10秒后每0.5秒采20点记录闲置 |
| 工作量 | 可获得时记录布局 full/incremental、度量行数、选区矩形数、缓存命中、扫描次数/节点数、rows构建次数；拿不到记 N/A，不能猜数 |
| 完整性 | 保存/复制后的内容哈希或精确文本比较；目录结果与预期清单对比；正常退出、没有丢失脏稿 |

采样频率本身可能影响低配性能：先用空白页测采样脚本开/关差异，脚本在另一进程运行，CPU与内存不并入应用。若开销明显，降低频率并统一全部对照。日志/截图不要逐鼠标事件同步写磁盘；原始事件时间可以有界缓冲后保存。

`NEO_TABS_TRACE` 为现有可选诊断接口。主体验基线先不启用，必要时选关键场景以新轮次补跑，设置为独立日志路径；不能把有 trace 与无 trace 的数字直接混报。现有 trace 未覆盖的阶段记 N/A；允许临时外部采样，不改生产源码加入打点。

时间约定：单轮拖选10–15秒；启动/目录等待最多60秒，大文档首次布局最多60秒。达到预算立即记录尚未完成/是否可操作，若已持续不响应则记 FAIL，先尝试正常关闭。不要在负载失控后继续更大样本；未跑扩展项写明因前置失败暂停。准备样本与等待用户处理不计入超时。

可用“≥100ms长帧、≥500ms明显停顿、≥2秒连续未响应”作本轮现象标签，属于诊断整理约定，不是已经批准的发布门槛。无法精确测帧时仅记录可见现象与证据，不填写虚构的p95/p99。

## 5. A组：拖选、滚动与复制

鼠标必须经过正常窗口输入链，不直接改内部 `InputState`。脚本可用正常鼠标/键盘注入或现有 Win32 探针方法，操作前确认目标窗口位于前台、鼠标起止点确实属于编辑区。自动化失败不得算应用卡顿；失焦、误点菜单或窗口移动要保留并重测。

所有拖选从相同窗口、相同文档位置开始；记录指针轨迹、滚动方式与频率、按下/松开时间、最终选区大小。优先复现用户“按住左键并滚动划选”的方式。轮滚、指针到边缘跟随滚动分别标明，不假设程序支持某种自动滚动；不支持时记行为，并用实际支持方式补测。

| ID | 步骤 | 必须记录 / 预期 |
| --- | --- | --- |
| A00 | 空白页，静置后固定轨迹移动鼠标，采样开/关各跑一轮 | 测量脚本与普通界面的开销基线 |
| A01 | J80默认语言/默认换行，纯滚动10秒，不按鼠标 | 区分滚动与选区负载；注明JSON默认可能不开换行 |

| A12 | 从上述选区输入短字符串、撤销，再保存运行副本 | 替换/撤销/保存内容精确恢复；操作后正常退出 |

A07可用键盘构造不同起点作控制实验，但必须标 `keyboard-control`，不能替代A03真实拖选；测量开始后不持续发送成千上万次按键。若无法取得选区长度，可在复制结束后的验证阶段读取文本计数，别在拖动采样时不断复制选区制造额外开销。

原因判断需要关联工作量：纯滚动同样慢意味着不能只归因选区；选区长度变化但可见绘制数不变时，检查全文传递、回调复制、度量与缓存等其他项。无法分段测量时，明确只取得端到端基线。
