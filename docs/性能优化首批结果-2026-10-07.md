# 性能优化首批结果（2026-10-07）

已验收的表格、图片和任务框修复保存为本地提交 `44123ad`，没有推送。本批继续处理性能计划中已经观察到的单行 JSON 常驻 CPU 热点；新的性能改动和记录保留在工作树，提供独立候选供实机验收。

## 改动和证据

输入组件原来只按垂直可见行限制工作。对不换行的 JSON，虽然 renderer 会裁剪，`components/input.h` 仍为整条长行的所有着色片段创建文字、背景和装饰节点；这些离屏节点继续进入布局、实例及渲染缓存。

本次只在创建片段节点之前按横向视口过滤，保留两侧至少 32 px/两倍字号的余量，避免裁掉墨迹和背景边缘。完整正文、样式段、caret 度量、命中和选区模型继续保留；部分可见片段保留完整原文和稳定节点 ID，横向滚动后相应节点重新出现。没有改正文存储、Markdown 解析、表格映射或 IME 路径，也没有降低渲染刷新策略。

新增 `input_horizontal_viewport` 用 2000 个交替中英文着色片段验证：优化前初始视口创建 2000 个文字节点，四个离屏断言失败；优化后只创建 11 个，但模型仍有 2000 个完整段。回归检查覆盖左右端、边缘片段完整文本、链接/背景/删除线/下划线、横向选区和正文不变。20 次稳定 compose 的一次信息性测量为 63.1 → 9.3 ms，不作为机器相关的测试门槛。

## 同机 A/B

最终报告使用带连续前台守卫的独立轮次：每组 3 次新进程、每轮先稳定 2 秒再采样 6 秒，间隔约 100 ms 检查 HWND/前台和进程 CPU/内存。CPU 取内核+用户秒数增量除以墙钟，100%=一个逻辑核；表中为三轮中位数，内存是采样稳定期的专用提交量，不是整个启动峰值。

条件：开发机、Win32/Direct2D Release x64、软件 Direct2D、窗口 DC；系统 DPI 120、UI 缩放 1、字号 16、行号开、可读宽度开、动画开、客户端 1262×753。各轮独立 APPDATA/TEMP、`NEO_SINGLE_INSTANCE=0`，未修改用户设置、注册表或工作集策略。样本沿用 2026-10-05 的生成 fixture 并校验 SHA256；文件没有变动。
