# EUI-Edits 开发流程与交接规范

本文件是新对话、新代理和维护者接手 EUI-Edits 时的第一入口。它定义工作顺序、证据边界和目录归属；当前实现与具体轮次结果分别见[文档导航](目录说明.md)和 `local-docs/`。

## 1. 接手先做状态快照

任何开发、构建或文档整理开始前，先在仓库根目录执行：

```powershell
git status --short --untracked-files=all
git branch --show-current
git rev-parse HEAD
```

阅读顺序固定为：

1. `AGENTS.md`：协作边界、构建和证据纪律。
2. 本文件：本轮流程和交付字段。
3. `docs/目录说明.md`：稳定文档、本地文档和 `out/` 的分层。
4. `docs/当前实现与验收路线.md`：当前源码边界和下一步入口。
5. 与任务直接相关的技术契约。
6. `local-docs/repo-docs/` 中最近轮次的交接、验收或测量记录（如果当前克隆存在）。

工作树已有的修改、未跟踪文件和 `out/` 证据默认属于已有上下文。不得用 `reset`、`clean`、宽泛删除、覆盖旧 `out/` 或回退未知代理的修改来制造“干净”。先把它们列入本轮状态快照；只有确认是生成物，才加入本机排除或移入专用证据目录。

“目录状态干净”在本项目中的含义是：生成物不散落在源码目录，已知业务改动可按文件和任务解释，证据有独立目录，剩余 dirty/untracked 均被交接记录标明。它不表示强行清空别人正在进行的工作。

## 2. 先定义任务和授权边界

开始编码前写清四件事：

- 目标：修复、功能、性能、文档或发布中的哪一类任务。
- 范围：允许修改的目录和明确不能碰的目录。
- 通过条件：测试、行为、指标或文档链接如何判定完成。
- 授权：构建和验证可直接执行；提交、推送、打标签、发布和删除未知材料必须有明确授权。

多代理协作时，主代理负责整合、源码核对、测试结论和最终交接。子代理使用有边界的只读盘点或互不重叠的文件范围；不得让多个代理同时编辑同一个生产文件，不得让子代理替主代理整合 dirty 工作树或发布。

## 3. 标准开发顺序

### 3.1 需求和设计

先找到现有实现、契约和回归测试，再决定改动点。跨域改动要明确数据域：UTF-8 源字节、投影文本、视觉行、几何坐标、选区和 IME 不能用未经说明的裸整数互相替代。缓存键必须覆盖文档身份、正文、装饰、字体、宽度和影响布局的版本。

性能任务必须先建立同规模、同配置、同轨迹的当前基线，一次只处理一个有证据的成本目标。微基准、源码猜测和理论容量不能直接变成整体 CPU、内存、输入到屏幕延迟或 GPU 收益结论。

### 3.2 实现和定向测试

生产代码、单元测试、测试资源和脚本一起更新；新增关键回归后核对是否被 `scripts/check-neoeditor.ps1` 的正式集合发现。先运行与改动直接相关的测试，再决定是否扩大范围。测试失败时保留日志和构建目录（排查结束后按第 4 节删除构建树），记录真实原因，不用旧日志替代当前候选。

### 3.3 正确性门禁

Windows/MSVC x64 Release 构建必须使用当前仓库内全新的唯一目录。PowerShell 脚本用 PowerShell 7（`pwsh`）；CMake 路径以本机实际安装为准。示例：

```powershell
pwsh -NoProfile -File ./scripts/check-neoeditor.ps1 `
  -BuildDirectory ./out/check-<唯一名称>/build `
  -CMake 'D:/ruanjian/Microsoft Visual Studio/Community/Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin/cmake.exe' `
  -Python D:/Python312/python.exe -Parallel 6
git -c core.whitespace=cr-at-eol diff --check
```

构建目录已经使用过就换新名称，不覆盖旧输出。记录 configure、build、CTest、翻译检查和 `diff --check` 的退出码，实际测试集合以当前脚本为准。

### 3.4 性能、真实窗口和打包

正确性、性能、真实窗口和独立打包分开验收。性能记录预热、原始轮次、P50/P95、指标定义、配置、窗口尺寸、DPI、GPU/适配器、源码身份和 EXE SHA256；工作集、私有工作集、私有提交和 GPU 指标分别记录。

真实窗口验收绑定目标 EXE、独立 APPDATA、所属窗口、实际操作、保存/撤销结果和正常退出。单元测试、模型测试、截图或 `EndDraw` 成功不能替代真实操作。设备、低配、IME、多屏 DPI 或持续拖选没有实际覆盖时写 `SKIP` 或 `NOT_RUN`。

正式包使用 `scripts/package-neoeditor.ps1` 的新构建和新输出目录。开发 EXE 不能改名冒充发布包；包验收记录最终资产哈希和版本。提交、推送、标签和发布另行确认。

## 4. 构建产物与 out/ 构建区

`out/` 只保留小体积证据和两类构建区，禁止长期堆放 CMake 构建树：任何含 `CMakeCache.txt` 的目录在当轮验收结束后即删除（含失败轮次排查结束后的构建树），`out/` 只留 exe/assets、日志、截图、原始数据与哈希。开发期增量编译复用仓库内的固定开发构建目录（如 `build-eui-tests/`），不在 `out/` 内新建。

### 4.1 预览轮换区（小改动）

- 目录固定为 `out/preview-1/`、`out/preview-2/`、`out/preview-3/`，`out/` 中同时最多只有这 3 份预览产物。
- 小改动默认流程：增量构建 → 把 `neo_editor.exe` 和 `assets/` 覆写拷入**最旧**（按目录修改时间）的 preview 目录 → 起 EXE 截图预览。不跑全量门禁、不出哈希报告，目录内除 exe/assets 只留当轮截图和简要说明。
- 未验证的小改动不单独累积成构建产物；改动累积由主代理记账，达到合适节点（一个功能闭环或一批修复）时主动向用户提出是否出可用版本。

### 4.2 稳定版候选区（可用版本）

- 出可用版本时：正确性门禁仍按 3.3 使用唯一新目录；打包按 3.4 使用全新构建与输出目录，最终 EXE+assets+SHA256 放入 `out/stable-candidate/`，随后删除门禁与打包的构建树。
- 用户在 `out/stable-candidate/` 上测试确认可发版后，**就地改名**为 `out/stable-v<版本>-<YYYYMMDD>/` 归档（如 `out/stable-v0.1.3-20261011/`）。
- `stable-v*` 归档只保留最近 3 个；淘汰前确认其中的哈希记录已并入对应发版文档。
- `stable-candidate` 未被用户确认前不得被下一轮候选覆写；确需替换时先向用户说明。

## 5. 状态和证据口径

所有验收表使用以下状态：

- `SOURCE`：只检查了源码或静态结构。
- `PASS`：指定动作已执行且满足断言。
- `FAIL`：指定动作已执行且不满足断言。
- `OBSERVED`：观察到现象，但没有足够条件形成通过/失败结论。
- `SKIP`：本轮有明确工具、设备或范围原因未执行。
- `NOT_RUN`：尚未执行，不能根据历史记录推断。

历史结果只对其源码、EXE、配置和轨迹负责。不能跨构建相减、把旧门禁数量当作当前数量，或把旧报告改写成新一轮通过。原始日志、哈希、截图、构建目录和测量数据放 `out/`；记录方法、结论和缺口的轮次文档放 `local-docs/`。

## 6. 文档分层

| 位置 | 应放内容 | 不应放内容 |
|---|---|---|
| `docs/` | 稳定技术契约、长期运行/构建流程、当前维护入口、可复查的产品边界 | 日期绑定测量、逐轮验收、临时计划、个人避坑汇编 |
| `local-docs/` | 当前克隆的交接、轮次验收、性能报告、旧计划、维护者笔记；不纳入 Git | 需要随项目克隆传递的稳定接口契约 |
| `out/` | 构建、日志、原始数据、截图、哈希、配置和 GUI 证据 | 手工维护的长期说明 |

`local-docs/` 由 `.git/info/exclude` 排除，不依赖根 `.gitignore`。本地文档缺失时，不能把其中的结论当作可复现事实；以当前源码和新证据为准。稳定文档可以链接本地记录作为当前克隆的复查入口，但应说明其本地性质。

## 7. 每轮交付和交接

每轮结束前运行 `scripts/write-handoff-summary.ps1` 生成新的本地快照。它不会覆盖旧快照，也不会修改源码或 `out/`。交接至少包含：

```text
目标与完成条件：
源码身份：分支、HEAD、dirty/untracked 文件、关键源码哈希
修改：实际文件、行为/API、未采用功能及原因
构建：仓库根、唯一构建目录、生成器、x64/Release、CRT、配置
验证：定向测试、门禁、翻译检查、diff --check、EXE 路径和 SHA256
真实窗口/性能：配置、覆盖范围、指标和状态
证据：out/ 原始日志/数据路径，local-docs/ 记录路径
剩余缺口：NOT_RUN、SKIP、FAIL 及停止原因
下一步：一个具体动作、源文件或脚本、通过条件
授权状态：提交/推送/标签/发布是否明确授权
```

下一位执行模型先读这份快照，再读 `docs/当前实现与验收路线.md`，不得仅凭提交号假设当前能力；本项目允许 dirty 补丁和未跟踪新增文件共同构成候选，必须以快照中的文件清单和哈希为准。

- [ ] 生产源码、测试、脚本、长期文档和本地记录放在正确层级。
- [ ] 新增关键测试已核对正式门禁集合。
- [ ] 门禁与打包使用唯一新目录；`out/preview-1..3` 轮换覆写与 `stable-candidate` 改名符合第 4 节构建区规范。
- [ ] 当轮 `out/` 内的 CMake 构建树已删除，只留证据与两个构建区。
- [ ] 测试结果和覆盖缺口使用明确状态词。
- [ ] 迁移后的文档链接可解析，日期报告不留在 `docs/`。
- [ ] 已生成新的本地交接快照。
- [ ] 未在没有授权时提交、推送、打标签或发布。
