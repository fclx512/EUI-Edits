## 能借鉴什么

| 机制 | 上游实际实现 | EUI-Edits 的对应情况与取舍 |
| --- | --- | --- |
| Tinta 视口优先布局 | 先排到当前滚动位置后约两个视口，后续按约 10 ms 的 UI 消息预算继续；预算检查在顶层块之间。[布局源码](https://github.com/oipoistar/tinta/blob/db70698e49a1f700c7ad98add1bebe713ac796bd/src/render.cpp#L3274-L3344) | 适合作为首屏渐进布局的参考，但单个巨块仍可能超预算。EUI 已有可见行细节按需度量，若首次布局仍是热点，应测粗几何建立、精排和滚动锚点，再考虑分片；不能只给现有全量循环套异步外壳。 |
| Tinta DirectWrite 行缓存 | 缓存上限 256 项、按使用时间淘汰；编辑、字体、宽度与换行变更清缓存。[编辑源码](https://github.com/oipoistar/tinta/blob/db70698e49a1f700c7ad98add1bebe713ac796bd/src/editor.cpp#L100-L131) | 有界缓存和失效计数值得参考。EUI 已有文本测量/渲染缓存，先测命中与超容量抖动。本轮实际发现的是离屏着色片段仍进入 UI 树，已先用横向视口过滤解决，未照搬另一套缓存。 |
| Muffin 块级懒布局 | 为全体顶层块建估算高度槽，再提升可见/光标块；提升的详情继续驻留。[源码](https://github.com/jstzwj/Muffin/blob/45418778f9a1e92bcfeffe23c611b57b2f45ab81/src/render/DocumentLayout.cpp#L857-L940) | 与 EUI 紧凑 caret 度量不同，值得做普通段落的小原型。但必须有详情预算、估算高度修正和滚动锚点契约；长单段和表格仍需单独处理，不直接迁移整个布局模型。 |
| Muffin 稳定位置 token 与 treap | 结构 splice 只替换变化范围，后缀垂直偏移通过 lazy tag 保留，查询 rank 时再解释。[源码](https://github.com/jstzwj/Muffin/blob/45418778f9a1e92bcfeffe23c611b57b2f45ab81/src/render/LayoutPositionIndex.cpp#L32-L160) | EUI 的连续行表和几何前缀仍有后缀遍历/重建成本。这是比“换 parser”更具体的后续候选；先用真实 LP 编辑基准确认比例，再用现有精确几何作为 oracle，保护表格字节映射、选区与折叠。 |
| Muffin 合并命令状态刷新 | 多种编辑信号共用一次排队刷新，捕获不可变命令上下文后只遍历一次命令表。[源码](https://github.com/jstzwj/Muffin/blob/45418778f9a1e92bcfeffe23c611b57b2f45ab81/src/app/MainWindowActionBinder.cpp#L98-L230) | EUI 状态栏已按 revision 缓存统计。若输入 trace 证明菜单/命令谓词重复工作明显，可借鉴合并快照；不因上游采用就直接增加另一层调度。 |
| Muffin 按 dirty region 查块 | 只查询脏区相交块并保留绘制边距，动画 host 单独按完整视口更新。[源码](https://github.com/jstzwj/Muffin/blob/45418778f9a1e92bcfeffe23c611b57b2f45ab81/src/editor/EditorViewPaint.cpp#L115-L195) | EUI runtime 已有 dirty rectangles、scissor 和子树 bounds。可进一步核对输入组件内部粒度，尤其光标闪烁时不应重建全部长行片段；本轮横向节点过滤就是当前已测热点的局部处理。 |

Muffin 还把部分节点标量打包，将少数类型才使用的元数据放入惰性 payload，项目自测的 block/inline 对象分别减少 96 字节。这提醒 EUI 的 C 组账本也应统计行/装饰对象固定字段与未使用的 rich metadata，而不只统计正文；是否值得拆可选 payload 要用当前对象数量和访问成本实测决定。[节点瘦身记录](https://github.com/jstzwj/Muffin/blob/45418778f9a1e92bcfeffe23c611b57b2f45ab81/docs/large-document-performance-2026-07-10.md#L178-L211)

Muffin 使用 piece table 和局部安全块解析，但 replace 成本随 piece 数增长；解析工作线程会丢弃过期结果，却不能取消已经开始的 cmark 解析。Tinta 启动仍同步读全文和 parse，编辑换行也会扫描全部逻辑行。因此两者都不能直接证明“任意大文档瞬时打开、常驻占用有界”。Muffin 自测的 100 MiB 密集混合样本仍记录约 17.6 秒解析、9.4 秒布局索引和 3013 MiB 重开工作集；普通散文数据更小，应按样本结构分别解读。[上游性能报告](https://github.com/jstzwj/Muffin/blob/45418778f9a1e92bcfeffe23c611b57b2f45ab81/docs/large-document-performance-2026-07-10.md#L121-L229)

## Mermaid 的收益比

EUI-Edits 当前没有 Mermaid 图表 renderer；`mermaid` 围栏仍显示为代码。Mermaid 暂不排入近期实现，只记录以后确认需求时可评估的路径。当前偏好是保持原生自绘方向以控制常驻占用，并在真正显示 Mermaid 图块时按需创建 renderer；低占用收益、语法兼容范围和绘制成本都还需要验证。

Tinta 的 C++ parser/layout 自绘图元可作为原生实现的外部参考，但图类数量不等于 Mermaid.js 兼容率：其测试明确包含未知语法回退和某些新 flowchart 语法拒绝。[Tinta 图表接口](https://github.com/oipoistar/tinta/blob/db70698e49a1f700c7ad98add1bebe713ac796bd/include/mermaid_ext.h#L19-L46)、[测试](https://github.com/oipoistar/tinta/blob/db70698e49a1f700c7ad98add1bebe713ac796bd/tests/mermaid_tests.cpp#L143-L389)

未来可比较两个方案：实现覆盖常见图种的原生自绘子集，超出范围时保留可读源码；或把官方 Mermaid.js 作为可选、按需的兼容引擎。原生方案可能避免额外浏览器 runtime 的常驻占用，但 parser、布局、字体测量、语法兼容及维护成本尚未测量。官方 Mermaid.js 依赖 DOM 环境；WebView2 是 native Windows 应用可选择的浏览器宿主之一，不是 Mermaid.js 的绑定要求。其他 DOM 宿主也需要评估运行时、启动、内存和集成成本。官方 `render()` 是异步 API，但 Promise 不代表计算自动进入 worker。[Mermaid 官方 API](https://mermaid.js.org/config/usage.html)

若将来评估，可用固定版本官方 Mermaid.js 与官方语料作为兼容性 oracle，先测拟支持图种的接受率、渲染可读性与边缘语义，再比较 Tinta 的自绘输出和拟新增的原生子集；同时按需加载候选 renderer 并测冷/暖时间、整个进程树的专用提交量、包体积、缩放主题和失败回退。WebView2 Evergreen 可共享系统 runtime；Fixed Version 官方说明体积超过 250 MB。Mermaid Tiny 能缩小 JS 包，但有图类和布局引擎取舍，且不会消除 DOM/runtime 需求。[WebView2 部署说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)、[Mermaid Tiny](https://mermaid.js.org/config/usage.html#tiny-mermaid)

通用绘制方法可以从公开可验证的 renderer 与图表样例中归纳；Codex 内部图表实现细节未知，本评估不对其架构作断言。本轮只记录取舍，不安装 runtime、不做 spike、不新增图表功能，也不改变原生主架构。

## 下一批的顺序

1. 验收[长行横向片段优化](性能优化首批结果-2026-10-07.md)，补实际拖选轨迹及跨屏选择的功能问题，区分输入事件、命中和绘制成本。
2. 继续现有 C 组的首开/换行/编辑账本；若布局收尾确为主项，优先试稳定位置索引与局部后缀几何，不先替换全文存储。
3. 若首屏建立是主项，再试普通段落的预算化精排；保留完整正确性 fallback，并测冷/暖与滚动后驻留。
4. Mermaid 只记录为未来可选功能：届时先用官方语料 oracle 比较常见子集的原生自绘与按需官方引擎，再决定是否值得立项；近期不排实现或 WebView2 实验。
