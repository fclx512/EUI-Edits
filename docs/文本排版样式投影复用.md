# 密集样式行的临时投影复用

`components/input_model.h` 中的 `InputModel::StyledProjection` 只属于一次物理源行的同步排版。它保存这一行去掉隐藏标记后的文本，以及投影偏移到源字节偏移的索引；行排版返回后释放。它不跨文档、帧、撤销、外部回写或 IME 更新保留，也不缓存字体度量、断行或光标结果。

普通样式片段的原路径需要为每个片段扫描此前的隐藏区间，生成该片段的投影字符串；全行与每个软换行段会重复这些操作。对于隐藏区间和可见片段都至少32个、且具有有效换行宽度的行，临时索引先生成一次投影文本，再按片段切取；源字节边界通过有序索引查询。少标记、少片段及无换行宽度的行沿用原算法。

## 映射与度量契约

- 输入隐藏区间沿用原有规范化语义：排序、互不重叠；首尾相接的区间可以分开保存。
- 同一投影偏移对应多个源间隙时，索引的 `lower_bound` 保留原 `unprojectVisible` 的“洞之前”锚点。相邻区间的重复投影间隙不能合并成错误的源锚点。
- 索引保存源字节与投影字节，不能把中文字符数、Unicode码点数或视觉行号当作字节偏移。
- 每个片段仍用原字体、字号、字重和文本度量入口独立测量，再按原顺序拼接 caret 与样式 run。没有用整行宽度相减推导片段推进量，因此不改变原有浮点累积和字形边界。
- `layoutStyledRangeImpl<false/true>` 在编译时分开普通与索引路径；普通入口保留原签名，避免每个短行片段增加索引条件分支。
- 表格等其它调用者继续走普通入口。原位导图、隐藏行、字体路径作用域和现有布局缓存的身份/失效规则不由这一索引替换。

临时内存随当前物理行的源文本和隐藏区间规模增长，不是固定进程内存上限。它没有持久缓存预算或淘汰策略；若以后改变为跨次复用，必须重新定义完整身份、失效和预算，不能延长这个局部对象的生命周期。

## 回归与测量

现有正式 `input_model` 回归加入源/投影边界与逐字节切片的精确等价检查，包括中文、emoji、相邻标记和样式片段的源区间；同一目标已在 `scripts/check-neoeditor.ps1` 的正式名单内。输入导航、行映射、视口度量、Live Preview、表格选区与字体缓存回归继续独立执行。

本机测试台专项为 `euiedits-wrap-cpu`，方法见外置工具的 `docs/wrap-cpu.md`。候选比较需要同轨迹、同配置、逐步几何核对与原始进程轮次；字体文件、源码、探针和依赖身份一并保存。日期绑定数据与负例保存在 `local-docs/performance/` 和 `out/`，不作为本契约的普遍收益承诺。组件CPU结果仍不证明真实持续 resize、输入到屏幕时延、GPU或完整应用验收。
