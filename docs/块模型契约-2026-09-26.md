本契约定义 Live Preview 呈现层的块间距模型。语义层 `LpLine` / `LpSpan` 不增加呈现字段；
块类型、范围、嵌套深度继续由既有计划提供。

## 0. 实测总纲：LP 的块间距装在行盒内部

Obsidian 的 Live Preview 逐行 `top` **首尾相接**：本次实测 112 行里除表格部件那一次外，
`rect.top[i] - rect.bottom[i-1]` 全部为 `0`（±0.01 舍入）。块间距不是在行之间，而是
**行盒内部的 `padding-top`**：

```css
.cm-s-obsidian .cm-line.HyperMD-header { padding-top: var(--p-spacing); }            /* 16px */
.cm-s-obsidian .cm-line.HyperMD-header + .cm-line:not(.HyperMD-header):not(:has(>br:only-child)) {
  padding-top: var(--p-spacing-empty);                                              /* 0px */
}
.cm-s-obsidian .cm-line.HyperMD-header + .cm-line:not(.HyperMD-header):has(>br:only-child) + .cm-line.HyperMD-header {
  padding-top: 0;
}
```

（`app.css` 11773–11781；`--p-spacing: 1rem` = 16px，`--p-spacing-empty: 0rem` = 0px。）

由此得到 R1 的两条**硬结论**，它们推翻了第一版候选表的多数 16px：

1. **段与段的分离由空源码行自己的 24px 承担**，不再叠加 `--p-spacing`。
   LP 里段落之间没有块级外边距 —— 实测「空行 → 段落」的段落行 `padding-top: 0px`。
2. **只有标题行与表格容器两处**会额外顶开间距：
   - 标题行：`padding-top: 16px`，唯一例外见下面第 3 条；
   - 表格：LP 把表格换成 `.cm-embed-block.cm-table-widget` 部件（不是 `cm-line`），
     实测 `padding: 16px 16px`、`margin-left/right: -16px`，部件高 121.6 = 16 + 3×29.6 + 16。

阅读视图（`--heading-spacing: 2.5rem` = 40px 前距、块间 `--p-spacing` 16px）是**另一套**
规则，其数值不得搬进 LP。

## 1. 字段与所有权

| 字段 | 写入者 | 读取者 | 默认值 | 等价性 |
|---|---|---|---:|---|
| `LineDecoration::spaceBefore` | `blockSpaceBeforeFor(plan, index)`（lp_decorations.h） | `appendMeasuredLine`，只复制到块首源行的第一条可视 `TextLine` | `0px` | `0px` 时与旧几何逐位一致 |
| `TextLine::spaceBefore` | `appendMeasuredLine` 在 `firstNew` 段盖章 | `rebuildGeometry` 构建 `LineGeometryTable` | `0px` | 非块首、续行、隐藏行均为 `0px` |
| `LineGeometryTable` 的 gap | `build(heights, spaceBefore)` | `top/bottom/lineAtY/total` 及所有现有 Y 消费者 | 无额外 gap | 全部 gap 为 `0` 时复用旧前缀和 |

`spaceBefore` 是块首行的上方间距，单位为像素，必须为非负值。它不属于行高：
`TextLine::lineHeight` 只表示纯文字行盒高度，`bottom(i) = top(i) + height(i)` 不包含下一行的 gap。
`LineGeometryTable` 的旧重载 `build(heights)` 等价于 gap 全 0，**逐位不变**。

## 2. 几何公式

对 `n` 条可视行：

```text
top[0] = 0
for i in [0, n):
    top[i] = y
    y += max(height[i], 0)
    if i + 1 < n:
        y += max(spaceBefore[i + 1], 0)
total = y
```

（实现里等价地写成"进入第 i 行前先加 `spaceBefore[i]`，`i == 0` 忽略"。）

最后一行不产生尾部 gap。隐藏行的高度和 `spaceBefore` 都按 `0` 处理（`rebuildGeometry`
两处都显式归零），折叠不会留下幽灵间距。gap 区域命中上一个行索引（`lineAtY` 用
`upper_bound`，落在下一行 `top` 之前都算上一行）；选区矩形只覆盖行盒本身，不填充 gap。

## 3. 生成规则（R1 实测版）

`blockSpaceBeforeFor` 只看**本行与前两条源行**（不看可见性、不看折叠），返回 `0` 或 `16px`：

1. **首条源行**（`index == 0`）恒为 `0`：文档顶端没有外间距。
2. **标题行**：`16px`，唯一例外是「**标题 + 恰好一条空行 + 标题**」→ `0`
   （对应 `app.css` 11779 那条规则，`:has(>br:only-child)` 就是"这条空行只有个 `<br>`"）。
   隔了两条及以上空行时例外**不生效**（规则只认紧跟的那一条空行），仍是 16px。
   注意例外要求"空行的前一行是标题"，不是"前方最近的非空行是标题"。
3. **表格容器**：上内边距落在**整张表的首行**（`tableId >= 0 && 前一行的 tableId` 不同）；
   下内边距落在表后紧跟的那一行上（`前一行 tableId >= 0 && 本行 tableId` 不同）。
   `spaceBefore` 只有"行前"这一个自由度，下内边距因此只能由后一行承接。
   语义层故意把每个表格行都标成 `blockFirstLine`（逐行活动源码），所以**不能**按
   `blockFirstLine` 直接发作间距 —— 必须借 `tableId` 认整表边界。
4. **其余一切**（正文、引用、列表项、代码行、分隔线、frontmatter）恒为 `0`：
   LP 里它们的分离已经由空源码行的高度给出（见 §0）。
5. 两处规则同时命中时取 `max`（不会叠加成 32px）。
6. 软换行续行不继承 gap：`appendMeasuredLine` 只给本源行的第一条可视段盖章。
7. **增量路径的邻域必须是 ±2**（`buildDecorationsIncremental` 的 (e)）：规则 2 要回看
   前两条源行，半径 1 会让"把前两行改成标题"这类编辑照抄旧 `spaceBefore`。
   邻域膨胀必须排在**围栏扩块 (f) 之前** —— 膨胀可能牵进一条代码内容行，扩块才是把它的
   开围栏一起拉进来的那一步；顺序反了会撞上 ⑤ 的不变量（重算段里有代码内容行却没连
   围栏一起重算）而白白退全量。
8. `LineDecoration::operator==` 与增量复用的 `decorationsEquivalent` 都必须比较
   `spaceBefore`，否则纯间距修改会命中旧排版缓存。

### 实测数值表（16px 正文；与第一版候选表的差异已按 LP 实测改写）

| 前一非空块 | 当前块 | `spaceBefore` | 依据 |
|---|---|---:|---|
| 无（文档首块） | 任意 | 0px | 顶端无外间距（几何也忽略 `spaceBefore[0]`） |
| 任意 | 正文 / 引用 / 列表项 / 任务项 | **0px** | LP 段落行实测 `padding-top: 0`；分离由空行的 24px 给出 |
| 任意非空块 | 标题 | **16px** | `.cm-line.HyperMD-header { padding-top: var(--p-spacing) }` |
| 标题（后跟恰好一条空行） | 标题 | **0px** | `app.css` 11779 的第三条规则 |
| 任意 | 代码行 / 围栏行 | **0px** | 实测 LP 代码行 `padding: 0`（阅读视图 `pre` 的 12px 不适用） |
| 任意 | 分隔线行 | **0px** | 实测 `hr` 行盒 24px、`padding: 0` |
| 任意 | 表格首行 | **16px** | `.cm-table-widget { padding: 16px }` 的上边距 |
| 表格非首行 | 表格行 | **0px** | 部件内部无行间距；靠 `tableId` 认出整表首行 |
| 表格末行 | 表后第一行 | **16px** | `.cm-table-widget { padding: 16px }` 的下边距 |

同一列表的相邻项、嵌套深度、引用层级按上表一律为 0 —— 它们的视觉差异来自行盒自己的
`padding`（列表 1.2px）与左缩进，不是块间距。

## 4. 标题行盒

Live Preview 标题行盒回归**纯文字高度**：h1/h2 = `1.2 × 字号`、h3 = `1.3 × 字号`
（`--h1-line-height` 1.2 / `--h2-line-height` 1.2 / `--h3-line-height` 1.3）。
`MarkdownStyle::h1/h2/h3LineHeight` 里烤着旧的 "+1em 上置留白"，且还有独立的只读
Markdown 渲染器消费这三个字段，**R1 不全局修改它们**；LP 侧由 `lineSizeFor` 自己按比例算，
旧版在 LP 中叠加的 `1em` 上置留白改由 `spaceBefore` 承担，且不再设置标题 `textShiftY`。
行号槽、光标、选择和点击命中都使用同一张包含块间距的几何表，不会被标题行高撑大。

### 已定性但**刻意不复刻**的 LP 伪影：标题行盒多出的 ~4px

同一 h1 在阅读视图里行盒是 31.06px，在 LP 里却是 **35.06px**（h2：28.06 → 31.26；
h3：27.41 → 29.81）。DOM 实测（隔离实例，`build/heading_dom.json`）表明这 4px 来自
CodeMirror 的游标锚点：

```html
<div class="cm-line HyperMD-header HyperMD-header-1">
  <img class="cm-widgetBuffer" aria-hidden="true">   <!-- height:1em, vertical-align:text-top -->
  <span contenteditable="false"></span>
  <img class="cm-widgetBuffer" aria-hidden="true">
  <span class="cm-header cm-header-1">…</span>
</div>
```

`.cm-widgetBuffer` 是 1em 高、`vertical-align: text-top` 的 `<img>`；标题字体的
ascent+descent 约 1.45em，大于 `line-height` 的 1.2em，负半行距把行盒顶到约 1.35em。
正文行（line-height 1.5 > 1.45）里这一项正好抵消，所以空行/正文仍是干净的 24px；
只有标题行（1.2/1.3）会中招。这是**渲染器实现痕迹**（依赖本机 CJK 字体的度量，换台机器
就连数值都不同），不是 Obsidian 的设计意图 —— 阅读视图用同一份 CSS 却给出精确的
1.2em/1.3em 即为佐证。R1 因此采用 CSS 声明的比例，并接受"每个标题行比 LP 矮约
2.4~4px"的累计差；若后续视觉圈认认为不可接受，再单独立项讨论（届时也应按
`fs × 实测比例`而不是抄 4px 绝对值）。

## 7. 不变量与验收

- 所有 `spaceBefore == 0` 的输入，`top(i)`、`height(i)`、`total()` 与旧实现逐位一致
  （单测 `input_line_map::testGeometryTableWithGaps` 里的"全 0 gap 等价"用例）。
- gap 只出现在行盒**之外**：`bottom(i) == top(i) + height(i)` 恒成立，行高与文字位置不受影响。
- 每个块首 gap 只出现一次；空行不会重复计数；软换行不会复制 gap；文档首块恒为 0。
- 隐藏行（折叠）高度与 gap 都是 0；`lineAtY` 在 gap 区间返回上一行。
- 语义层结构和 md4c 输出保持不变。
- 目标测试：`lp_decorations`（843 项，含新的 `testBlockSpaceBefore` 与增量等价性
  逐字段比较）与 `input_line_map` 全绿；整套 42 项里唯一失败仍是既有的
  1.25 DPI 中文光标偏移 10.0014px。
- T24 标本中的标题、段落、引用、嵌套列表、表格、代码块和图片场景均可指出对应的结构
  字段或参数常量，并在 `docs/渲染问题标本-2026-09-26.md` 里记录与 LP 的观感差距。

### R3 追加：表格行盒与网格（2026-09-26）

表格行不再靠"底色带 + 3px 分隔条"暗示结构（那是逐格网格线还没有时的权宜），改成
Obsidian 实测的**纯网格 + 无底色**：

- 行盒高 = 单元格行高 `bodySize × 1.3` + **上下各 `kTableRowPaddingYEm`(=0.275em ≈ 4.4px)**
  = 29.6px @16（Obsidian `padding: 4px 8px` 的实测行盒）。水平那 8px 在 input_model 的
  `kTableCellPaddingEm`。
- 文字位置：行盒变高而文字顶对齐的话多出来的空间会全落到文字下方，所以表格行的
  `textShiftY` 同时置 `bodySize × kTableRowPaddingYEm`，文字跟着下移同样的量。
- 表头下边框 = 分隔行自己的高度 `kTableSeparatorHeight`(=1px)：相邻格边框 collapse 后
  就是一根 1px 线。
- 表头 / 正文行**都不给底色**（`box.background` 留透明）。

不变量（新增两条，实机踩到的）：

- **`gridColor` 也算"有盒"**：`appendMeasuredLine` 的早退条件是"没有任何行级样式"，
  表格行去掉底色后，若只按 `background`/`barColor` 判断，`gridColor` 会被整行丢掉 ——
  现象是整张表只剩文字、连外框都没有。判据里必须带上 `box.gridColor.a > 0`。
- **排版层的宽度必须按渲染的 ppem 量**：`TextPrimitive` 收到的是设备像素字号
  （`toPixels(fontSize, dpiScale × uiScale)`），排版层拿到的是逻辑字号；带 hinting 时
  advance 被量化到整数像素、不是字号的线性函数，两端各取一次整就会差 6~10%，表现为
  每个样式段都溢出自己的矩形、压掉下一段的头一个字符。修法是
  `TextPrimitive::setLayoutPixelScale`（框架每帧设 `effectiveScale`）+ 本层继续用逻辑
  字号调用 `measureTextMetrics`。所以**本层（含几何表的宽度来源）与渲染层是同一套
  advance**；这条也是 input_model 里 caretX / run.x / 选区矩形能对齐字形的前提。
  明细与逐字符对照见标本"补充四"。
