# 性能测试方法与范围

性能结果绑定源码、EXE、夹具、配置与轨迹。日期报告和原始数据保存在维护者的 `local-docs/performance/` 与 `out/`；README 的摘要不是每台机器的性能保证。正确性测试、组件计时、真实窗口和独立包分别验收。

## README 闲置内存

README 只展示空白、三个小 Markdown 标签、9 MiB 纯文本和同规模 Markdown 的进程内存表。Windows 64 位 Python 的后台复测脚本为 `tests/probes/readme_memory_background.py`：

```powershell
D:/Python312/python.exe tests/probes/readme_memory_background.py `
    --exe ./out/preview-2/neo_editor.exe --out ./out/acceptance/memory-unique
```

输出目录必须全新。默认四场景各启动三次，加载后静置10秒，以0.5秒间隔采20点；统计每次启动的中位数，再跨三次取中位数。通过 EX2 分别读取整体工作集、专用工作集和专用提交，按1,048,576转换MiB，不相加、不修剪工作集。记录原始字节、样本范围、夹具/EXE哈希、配置、窗口大小/DPI、PID与退出码。

脚本以不激活方式启动，为所属 HWND 加 `WS_EX_NOACTIVATE` 夹具标记，保持可见、非最小化的 1280×800 无边框窗口（客户区同为 1280×800）并置于其它窗口下方；只读目标进程计数，以 PrintWindow 离屏截图记录内容。小标签沿用应用的私有TEMP文件/事件打开协议，逐个加载后停在第三页。它不发送全局鼠标或键盘输入，不置前。每轮验证 125% DPI、1280×800 客户区、20 点齐全和正常退出；窗口状态变化或加载/退出失败保留原始失败，不混入汇总。0.1.4 历史表使用 1262×753 客户区；0.2.x 无边框窗口的客户区等于外框尺寸，新旧表不逐项比较。

维护者外置测试台的 `euiedits-readme-memory` 调用该脚本并绑定源码/工具身份：`D:/Python312/python.exe D:/编译开发/eui-testbench/python/tb.py run euiedits-readme-memory`。探针整体为 `OBSERVED`，采样/身份断言可为 `PASS`。后台可见窗口与旧版前台窗口的条件不同，结果不能直接作为版本收益A/B；截图和文件打开也不能代替实际编辑/保存验收。

## 大源码文本与容量盘点

同一后台脚本支持 `--document <文件>`：将指定文件按原字节复制到新证据目录，仅测这个文档，记录大小、行数、SHA256；默认仍是原来的四个 README 场景。不要以同名 `sqlite3.c` 代替文件版本、字节数与内容身份。任务管理器的默认内存列通常接近专用工作集，比较时仍须核对页面和列名，同时保留总工作集及专用提交。

`input_memory_breakdown` 是需参数的无窗口容量盘点，不自动注册到 CTest：

```powershell
cmake --build ./build-eui-tests --config Release --target input_memory_breakdown --parallel 2
./build-eui-tests/Release/input_memory_breakdown.exe D:/fixture/sqlite3.c source viewport
# plain/source × viewport/full；同一文件、800×500、16px monospace、不换行。
```

它调用真实输入构建器和源码装饰器，报告行数组的 size/capacity/sizeof、正文副本、几何、caret、样式与 token 容量。视口详细度量已默认用于大文档；关闭它是配置对照，不代表当前默认。容器容量不是进程物理页或堆归因：字符串按 MSVC 内联存储排除重复计数；装饰表内部按身份去重共享样式与侧挂记录，共享装饰代次只计一次。控制块大小为近似值；旧容量报告的计数方法保留原状，不能直接将新旧总量差当作真实堆释放。未统计分配器元数据/空闲保留页、字体塑形缓存、窗口和渲染资源、应用其它状态，不能与 EX2 相加或相减作为残差归因。

通用视觉行保留精确的源字节范围、换行分段、宽高、行号。holes、样式段、行颜色及列表/任务图标由按需拥有的呈现记录提供，详细caret数组的容器头也按需拥有；普通空记录的读取/字节平移不分配。复制行时深复制这两类记录，移动保留数组身份；大文档离屏详情释放头与数组后仍保留精确宽度。图片、表格、折叠图标等已有稀有字段继续使用写前分离的侧挂记录。派生页面预算计入各记录头及动态容量，共享控制块为近似估算；它不是进程内唯一分配量，不包含分配器元数据。这一存储改动不采用估算行高或滚动时改变全文换行边界。

源码行缓存只保存字节长度、起点、相对 token 和词法状态，读取当前源正文进行词法分析；不长期保存借用的字符串视图。增量拼接先重算起点再传播词法状态。装饰与视觉行的样式段共享只读样式记录，写入前分离；颜色按完整值精确归一，不以容差合并。行装饰中的字体、框、图片与表格提示等稀有数据也按需侧挂。`edit()` / `editRare()` 返回的可写引用仅供即时修改，不得跨复制或发布保留；发布装饰表时冻结样式记录。

每线程共享样式字典最多保留256项，字体名超过4096字节不进入字典；满时清空字典，活跃快照仍持有自己的记录。默认空样式不分配。此字典不会持有文档，保留量有界，但属于线程全局资源，不计入单页缓存预算；字体名上限下约为1 MiB量级，不能称零驻留。legacy向量装饰按行保守计费，表内去重预算也只是近似容量。

维护者外置测试台的 `euiedits-compact-source-oracle` 对五类源码比较完整词法/装饰输出，包括UTF-8编辑、调色和preedit；`euiedits-compact-source-layout` 对SQLite的600/800/1200 DIP、换行/不换行六场景比较所有行的几何与源映射。`euiedits-compact-memory-ab` 记录三种大文档的ABBA与README四景；`euiedits-compact-wrap-baseline` / `euiedits-compact-wrap-candidate` 仍走既有29景组件轨迹。工具构建兼容旧/新存储接口，须验证同一个探针源码及编译入口，不能混用接口迁移前后的工具身份。

后台同夹具A/B可加 `--compare-exe <冻结基线>`，同时指定 `--document`：每批按 baseline→candidate→candidate→baseline 启动四个独立进程，默认三批。仍是每进程20点先取中位，再跨同角色六个进程取中位；保留所有配置、截图、原始字节、顺序、EXE身份与正常退出。维护者测试台 `euiedits-large-text-memory-ab` 调用此入口。

外置测试台 `euiedits-sqlite-memory` 测空白、指定 C 文件及同字节 txt 副本；两种扩展名的默认字体、换行和高亮可能不同，因此只是实际呈现对照。`euiedits-vault-edit-memory-inventory` 执行八项定向正确性测试和上述四组合容量盘点；修改其 plan 中的文档路径可复用自备源码，不依赖下载服务。

多行 `InputLayout::metrics` 仅镜像光标行的精确宽度，命中、选区和导航直接使用所属 `InputState` 的行详情；单行布局仍拥有完整 metrics。测量长行回调成本时，应另计布局自己的数组容量，不能只盘点行数组。`input_callback_layout` 的暖构建分配检查覆盖普通全局 `new/new[]` 的累计请求，并非专属堆归因；其阈值不等于进程内存收益。视觉行字段按对齐排列以减少常驻填充，所有字段精度和按需记录的所有权保持原有语义；实际行头大小以目标构建的 `sizeof` 为准。

## 目录扫描

`vault_scan_benchmark` 调用实际 `neo::vault::scan`，输出逐轮 JSONL。`scan_us` 是扫描、条目构造与排序的墙钟，包含文件系统等待；不含指纹校验、应用动作、后台调度、列表绘制或屏幕显示。它不是进程 CPU 时间。

在已配置为 Win32 / Direct2D、MSVC x64 Release 的本仓库构建目录运行：

```powershell
# 用本机 CMake 绝对路径替代 cmake（若未加入 PATH）。
cmake --build ./build-eui-tests --config Release --target vault_scan_benchmark --parallel 2
./build-eui-tests/Release/vault_scan_benchmark.exe 'D:/isolated-vault-fixture' 5 1 `
    > ./out/scan-unique.jsonl 2> ./out/scan-unique.stderr
$scanExit = $LASTEXITCODE
if ($scanExit -ne 0) { throw "scan probe failed: $scanExit" }
```

目录需自行准备；只扫描元数据，不读取正文。参数依次为根目录、正式轮数和预热轮数，默认 5、1。Windows 入口使用宽字符参数，支持中文路径。负数 `round` 是保留的预热行，不计正式统计。扫描失败、部分扫描告警或进程内树指纹变化均返回非零；应保存 stderr 和退出码，失败数据不能纳入通过结果。探针不能验证真实软件的输入、保存或退出。

公平 A/B 先冻结并留存两个 EXE，使用相同工具链和编译配置。每场景至少三批 `A → B → B → A` 独立进程；每进程先预热，再测正式轮次。按进程计算 P50、线性插值 P95，再对同角色的进程统计取中位数，保留进程 P50 最小/最大范围。不要把所有轮次混成一个中位数，也不要把不同配置的运行当作 A/B。

运行前后记录源码输入清单、EXE SHA256、夹具相对路径/类型/内容哈希与文件/目录数。两角色每一步的最终树指纹、计数和告警必须一致。应用缓存冷热与磁盘缓存冷热分开说明；自然文件系统缓存不叫冷磁盘。在用户仍使用的主机上，计时标为 `OBSERVED`，结构断言可为 `PASS`。

扫描器在 Windows 上复用目录枚举所得普通文件的类型，避免重复属性查询；目录、链接和不能确认的类型继续核对原有属性与 reparse tag。目录联接与符号链接目录作为叶节点，其他可枚举的 reparse 目录沿用原扫描路径。扫描不是原子快照：枚举后并发替换的条目可能到下次重扫才反映，不用这份元数据替代打开/保存时的文件安全检查。

## Markdown 变宽重排

字体解析与密集标记行投影分别见[字体路径复用](文本排版字体路径复用.md)和[样式投影复用](文本排版样式投影复用.md)。需要同时保留样式 Markdown、纯文本、固定宽度、不换行和反向收窄对照。固定 800 DIP 的 `editor_pipeline_benchmark` 不等价于连续变宽轨迹。

维护者外置 `eui-testbench` 的 `euiedits-wrap-cpu` 记录预热、逐步宽度与几何、字体文件、源码/库/EXE 身份并进行交错 A/B；该工具不随本仓库分发。几何一致和组件计时不能证明真实拖动窗口的显示时延。

## 大文档编辑、滚动与预编辑

`editor_latency_benchmark` 是无头 `InputModel → LP 计划 → 装饰 → InputLayout` 探针。
参数为 `--bytes 1048576|9437184 --format plain|markdown --mode edit|scroll|preedit|steady
--rounds 5 --warmups 2 --wrap 0|1 --preedit-growth 0|1`。夹具含中文、emoji、短行及固定密度 Markdown，
逐轮 JSONL 记录夹具指纹、几何、独立 cold/预热轮次、互斥阶段耗时和实际路径计数。
`preedit` 交替改变临时中文合成串，保留 `committed=false`；`scroll` 在顶部和最多
4096 DIP 之间往返。`--preedit-growth 1` 在中文单字与中文加 emoji 之间交替，覆盖候选串伸缩；默认0仍为等字节数替换。光标位于文档中部，禁用跟随光标；它不是完整输入组件或连续滚轮轨迹。

外置测试台提供独立计划 `euiedits-latency-stages`，从测试台根目录运行 `python/tb.py run euiedits-latency-stages --env EUI_LATENCY_EXE=<预先构建探针的绝对路径>`。该入口不构建、不打开窗口、不进入默认 all-background；默认八景覆盖1/9 MiB Markdown等长/伸缩预编辑、已提交编辑/滚动/静置与纯文本负例。逐进程保留cold/预热/正式JSONL，独立重建夹具并记录SHA256、源码/工具/EXE前后身份；清除全部宿主 `NEO_*` 实验变量后冻结环境。外层与嵌套LP分别统计，结构校验可PASS，计时为OBSERVED；预构建EXE另需构建收据。参数、P50/P95口径和失败保留规则见测试台 `docs/latency-stages.md`。这是采集入口，不是原生IME、输入到屏幕或整体性能验收。

仅此基准目标启用 `EUI_LP_STAGE_PROFILE`，进一步拆分行索引、扫描、复用核对、md4c
与收尾。内部阶段属于 `plan_us`，不得与其重复相加；阶段外的文本差分、复制和析构
仍计入外层耗时。正式程序不启用该宏。连续同正文 revision 的单行预编辑可由实际
文本差分尝试局部计划，仍验证源字节及块边界；跨行、代码围栏等无法证明的情况退回
全量。局部计划成功后保存实际临时差分；装饰层仅在相邻快照、相同正文 revision、临时状态及全部呈现键匹配时尝试区间重建，区间外结构核对失败仍全量。该差分不伪装成已提交编辑，也不发布已提交布局回执。等长替换与字节伸缩分别测量，保留编辑、滚动、静置和纯文本负例；计划复制、全文证明及装饰索引仍有线性成本，不能把局部命中解释为整条输入链局部化。

真实窗口可用 `NEO_TABS_TRACE` 分别检查候选停留、候选变化、提交和滚动；关闭态的
右键菜单不应替换预编辑计划缓存。记录目标 EXE、独立配置、夹具及退出码，并保存
实际候选框、中文提交和保存字节核验。组件基准与 compose 追踪均不包含 DWM 实际
显示时刻，不作为输入到屏幕时延；GPU、低配、多屏 DPI 和持续拖选须另验。

## 目录动作与真实窗口

外置 `euiedits-vault-cpu` 区分动作进入到返回的 `action_us`，与等待后台扫描完成并采纳的 `ready_us`。换根异步化可以缩短动作返回时间，同时让 ready 增加；两项都要保留。直接扫描探针的 `scan_us` 不能代替这两项。

完整应用还需绑定目标 EXE、独立配置、窗口/PID、实际操作、保存回执与正常退出。GPU、低配、IME、多屏 DPI、持续拖选和输入到显示未实际覆盖时保留 `SKIP` / `NOT_RUN`。工作集、私有工作集与私有提交分别报告，不相加；嵌套阶段计时也不相加。

`document_vault_loading` 的受控扫描测试覆盖 choose/navigate/parent、冷/暖缓存、成功/失败期间的中文/emoji 输入模型编辑、撤销/重做、真实 `saveDocument` 写盘、保存版本和外部回写冲突。扫描器被闸住用于证明处理顺序与后台隔离，不测真实大目录耗时或 ACL；编辑回调的正文/revision 结算由测试调用，不能写成真实 HWND 输入验收。后台产品的 WM_CLOSE 正常退出由独立进程测量覆盖，两者不合并为一条真实输入到保存轨迹。
