## 已有收益证据

这些是历史测量的复核摘要，各自绑定构建与轨迹，不能相乘、跨构建相减或外推成整体响应百分比。

| 测量 | 观察结果 | 能支持的结论 |
|---|---|---|
| 2026-10-10，约39/79 KB Markdown，组件变宽重排 | 10.939→1.430 ms、21.197→2.768 ms，约降低87%；固定宽度等负例仍保留 | 字体解析复用显著降低这些全量重排成本；不含渲染/消息泵/显示 |
| 2026-10-11，100/1000行纯文本 Input/UI，三臂各三轮 | 默认软件 DC→硬件优先 Hwnd：滚动帧 P50 降低51%–65%，进程 CPU/帧降低70%–87%；私有提交增加31–34 MiB | 客户区绘制/提交有显著收益；未覆盖 Markdown 装饰或真实持续拖选 |
| 2026-10-11，同一优化 EXE，硬件 Hwnd，完整/裁高图集 | 私有提交减少9.1–9.3 MiB；帧 P50 增加0.06–0.10 ms；1000行滚动 CPU/帧中位数增加约0.43 ms | 裁高回收部分内存，同时保留观察到的时间代价 |
| 同轮完整应用未操作静置 | 裁高减少8.22 MiB工作集、8.83 MiB私有提交；六次正常退出，采样 CPU 增量均为0 | 回收效果不限于组件探针；不证明操作中响应、功耗或始终零 CPU |

因此，当前可概括为“CPU 处理与硬件优先绘制相配合，在已测路径中显著降低 CPU 成本，并承担额外内存”。“轻微”的程度取决于目标机器；裁高后相对软件模式的剩余差值尚需同构建三臂测量，不能把旧差值直接减去9 MiB。

## 下一步顺序与完成条件

1. **冻结验收候选。** 清点保留 dirty/untracked，建立覆盖根 CMake、应用、框架、测试和脚本的源码身份清单；在全新目录构建正式正确性门禁和开发 EXE。完成条件：退出码、目标集合、日志、源码/EXE SHA256 可对应，不借旧门禁替代新候选。
2. **测清当前内存代价。** 裁高启用，用同一个 EXE 再测软件 DC、软件 Hwnd、硬件优先 Hwnd，固定配置与轨迹、交错三轮。补真实 Markdown LP 场景；检查物理输入污染并保留事件/帧关联。完成条件：当前组合的 CPU、P50/P95、独立内存指标及负例齐全，给出裁高后的真实差值。
3. **补完整应用验收。** 先常规中英/emoji Markdown 编辑、软换行、表格与反向/跨视口持续拖选、字体/主题变化、切页、撤销、外部回写，再真实 IME、resize、遮挡/最小化、设备丢失恢复、正常退出。顺带核对 toast/segmented 的当前视觉。完成条件：目标 EXE、独立配置和所属窗口明确，每项 PASS/FAIL/SKIP；模型/像素合同不代替操作验收。
4. **覆盖目标机器并决定默认。** 低配或集显、4K/高 DPI、多屏切换，确认实际适配器与软件失败回退；有电池目标才测功耗。完成条件：记录内存代价、视觉和稳定性，依据覆盖结果决定是否默认硬件优先；随后独立打包验收。提交和发布另按用户授权执行。
5. **导图单独收口。** 把菜单模态试装迁到代码块右上角切换、输入框内源码/视图；先解决正文映射、焦点/IME、滚动几何、缓存失效与可读回退，再测冷启动/大图/缩放。完成条件：只读查看不修改正文、撤销或保存状态，规模限制和超预算回退可复查。导图负载不作为全局渲染收益的替代证据。

完成上述验收后，再按实际阶段占比选一个残余 CPU 热点。彩色图集按需上传、图片恢复副本、DXGI/DeviceContext 等目前都是候选研究；不把理论容量或源码猜测当作收益。历史 OPT-001/002 未复现仍不等于已解决。
