## 要发给别人（没有开发环境的电脑）

现在这个 exe 依赖 VS 的运行库（`MSVCP140.dll` 等），本机装了 VS 所以能跑，
换台机器可能报"缺少 dll"。要发人就编译便携版（静态链接运行库）：

```bash
cmake -S . -B build-portable -G "Visual Studio 18 2026" -A x64 \
  -DCMAKE_POLICY_DEFAULT_CMP0091=NEW -DCMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded
cmake --build build-portable --config Release --target neo_editor --parallel
```

产物在 `build-portable\Release\`，整个文件夹拷走即可（约 5.5MB）。
验收方法：`dumpbin /dependents` 里不应再出现 `MSVCP140`/`VCRUNTIME140`。

## 改了代码之后怎么重新编译

代码不是我改完就自动生效的，要重新编译。**这件事不用你做**——跟任何一个代理说
"重新编译 neo_editor" 就行。要让命令自己跑的话，是这两行（本机 cmake 在 VS 里）：

```bash
env -u HTTP_PROXY -u http_proxy -u HTTPS_PROXY -u https_proxy \
  "D:/ruanjian/Microsoft Visual Studio/Community/Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin/cmake.exe" \
  --build "D:/ruanjian/NeoEditor/build" --config Release --target neo_editor --parallel
```

`env -u ...` 那串不能省：本机同时存在大小写两套代理变量，MSBuild 会因此崩溃，
报错长得像"编译器缺失"，很容易误判成 VS 装坏了。

编译完 exe 会直接覆盖 `build\Release\neo_editor.exe`，**关了应用再编译**（文件被占用会失败）。

## 最新一轮（2026-09-22 晚）：换字体大小不再乱跳

**你反馈的"换字体后同字号大小差一大截"已定位并修好。**

根因：程序以前把"每个字体自己的 ascender-descender 高度"当成字号来用。各字体这个值
差异很大（等线 1.04 倍、黑体 1.00 倍、微软雅黑 1.45 倍），于是同一个字号换一次字体，
字形最多差 **45%**。这跟你的设置无关，是程序的换算方式错了。

现在改成固定基准，**所有字体在同一字号下视觉大小一致**（残差 3.8% 以内，来自字体本身
的汉字设计）。

**怎么试**：`Ctrl+,` 开设置 →「自选字体」→「编辑器」→ 在列表里依次点几个字体
（黑体 / 微软雅黑 / 鸿蒙 / 等线），字形大小应该基本不变，行距也不变。

**一个要留意的变化**：为了让各字体对齐，字号的含义标准化了（现在 em = 字号 / 1.30）。
你现在用的鸿蒙在「编辑器字号 16」下比之前**小约 10%**；如果觉得小，往右点到 17~18 就找回原来的观感。
默认的微软雅黑反而比之前大 11%。

**同时撤掉了**上一轮加的"编辑区滚动按行停"——你反馈拖滚动条时会一直颤着去吸附，
现在回到框架原生的平滑滚动（和 Obsidian 一样）。滚轮滚动也不再抖。

**顺带修掉一个静默 bug**：自选字体以前重启后不生效（设置里存着，但启动时没读回来），
而且下次改任何设置时还会把字体选择覆盖成空。现在重启能正确保留。

> 想恢复到出厂状态：关掉应用，删除 `C://Users//123//AppData//Roaming//NeoEditor//settings.ini`。

## 又一轮改动（2026-09-22 深夜）：三项反馈

### 1. 文档库可以跳地址了

侧栏顶上那行路径**现在是输入框**（以前是只读文字）：

- 点它，`Ctrl+A` 全选，粘贴路径，**回车**。
- 从资源管理器复制路径（带引号那种）直接粘也行，首尾引号和空格会自动去掉。
- 路径是**目录**：在文档库内的会逐层展开并滚到那一行；在库外的会把文档库根切过去。
- 路径是**文件**：自动展开到它所在目录、高亮、并打开。

想试试：粘贴 `D://ruanjian//NeoEditor//参考` 回车 → 整个库换成"参考"目录。

### 2. 拖窗口边框时画面跟手了

以前拖边框要等松手画面才刷新（现在明白原因了：Windows 拖边框时程序主循环被系统
的缩放循环挡住，框架只记了个"待重绘"标志、没人去画）。现在改成拖拽期间直接同步渲染，
**边框和内容一起动**。这条是在框架层修的，所有示例应用都受益。

### 3. 「等宽 / 正体」开关删了

既然能自选字体，这个预设开关就没意义了（菜单「查看 → 编辑器字体」和设置面板里那行都没了，
设置面板从 8 行减到 7 行）。编辑区字体现在的规则只有一条：**自选了就用自选的，否则用系统正文字体**。
你之前如果设过这个开关，旧配置里的键会被自动忽略，不用手动清。

## 又一轮（2026-09-23）：间距、光标、清晰度、大文档不卡

**这一轮改了四件事，但自动截图验收碰上机器锁屏没跑成——下面的"怎么试"请你亲手过一眼。**

### 1. MD 预览的字/行间距收紧了

你说的"字/行间距都很大"找到两个原因：中文排版在每个字之间被硬塞了 4px（组件 bug），
行距数值又按错误的基准多算了 1.3 倍。现在预览的疏密和 ZCode 一致，字距正常。

**怎么试**：同一份文档在「文本」和「预览」之间切着看——预览的字距应当和文本一样紧，
行距略松一点（这是正文排版的正常留白）。如果还想更紧、和纯文本完全一样，说一声即可
（一行数值的事）。

### 2. 鼠标样式按反馈改了

文本输入区（编辑区、筛选框、地址栏）= 文本选择（I 形）；其余所有地方 = 默认箭头，
整个应用不再出现"手型"。

**怎么试**：把鼠标移到编辑区看是不是 I 形，移到菜单/侧栏/按钮上看是不是箭头。

### 3. 字体变清晰了

两个原因：字形以前落在半像素上（越常滚动的地方越糊，编辑区/侧栏全中招），
字号换算又是小数像素。现在都对齐整数像素了。

**怎么试**：看预览/文本里的中文，笔画边缘应当明显干净；滚动一段再看，不发虚。

### 4. 大文档预览不再卡（内容越多越卡的那个）

预览以前是"整篇一次性画出来"，还只渲染前 200KB。现在是"只画看得见的几十个块"，
**整篇都能看**。1MB、5MB 的文档滚动应该和小文档一样顺。

**怎么试**：打开一个大 md（几 MB 的），在预览里滚来滚去，应该不卡、不白屏、不跳内容。
