## 回放与分层 oracle

每个参考动作都应保存同一份夹具、输入序列、参考/候选身份和结果。判定分四层，前一层失败时后续截图不能把它“补成通过”：

1. **动作回放**：记录初始文档、窗口/DPI/字体/主题、焦点、滚动位置、鼠标按键或键盘/IME 序列，以及每个动作的逻辑坐标。真实输入由主代理按当前 computer-use 流程操作；仓库旧 Python GUI 脚本直接注入 Win32 输入，不作为本轮 GUI 证据方法。
2. **源内容 oracle**：每个 caret/anchor/active endpoint 用 UTF-8 源字节偏移表示并验证落在字符边界；编辑操作对比期望源字节切片/结果文本。换行先记录原始编码，再明确规范化规则（例如 CRLF/LF）；内容比较同时报告原始字节和按既定规则规范化后的结果，不能把规范化相等说成字节完全相同。
3. **投影与视觉几何 oracle**：将选区源范围映射到 Live Preview 可见字符/隐藏标记，再比较每条视觉行上的可见覆盖范围、caret 所属视觉行、x/y/文字带高度、裁剪和滚动偏移。先用结构化范围/几何断言定位差异，再观察 GUI；矩形数量不等于视觉行数（同一行可能分成多个 span）。
4. **GUI 外观证据**：对齐可见窗口状态后截图，结合录屏/动作时间和窗口身份检查遮挡、光标、IME 候选窗及实际响应。截图差分只能辅助发现样式/几何差异；字体栅格化、DPI、平台文本 shaping 可能造成可解释像素差异，不能覆盖源范围错误、漏字、端点错误或输入结果错误。

## 一致性与参数分类

必须一致的是用户可观察的基本编辑正确性：插入/删除/替换作用于预期源范围；光标与选区端点在合法 UTF-8 边界；正反拖动选中同一源区间；可见文字被正确覆盖且隐藏标记不产生虚假可见选区；键盘导航、滚动后命中、撤销/重做与保存内容符合输入序列；窗口重排后坐标仍对应当前视觉布局。这里要求的是可验证结果，不要求两个引擎内部算法或每个边界策略完全相同。

可单独采样并调优的样式参数包括字体族/字重/字号、行距与段间距、标题比例、列表/引用缩进、代码块行距和底色、表格 padding、选区颜色与圆角、光标宽度/闪烁周期。对比时记实际 Windows 字体回退、DPI、窗口尺寸、主题、Obsidian 版本和 CSS 来源；像素差异若来自引擎/字体栅格化可解释，但不能免除以上正确性。
