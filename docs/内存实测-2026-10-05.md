# EUI-Edits 0.1.0 内存实测（2026-10-05）

本记录用于更新中文 README，再据此同步英文 README。测量的是已发布的静态 CRT 单 EXE，在真实窗口加载完成后闲置时的单进程内存。它不代表启动峰值、编辑/保存峰值、长时间滚动或所有文件的上限。

## 测试对象与环境

- EXE：`out/euiedits-0.1.0-single-exe/EUI-Edits-0.1.0-windows-x64.exe`，3,671,552 字节。
- SHA256：`c3176a0c079fb189015a6efee943e415a2a761d0890e0c6eed5842f3fbf6f19d`，与旁置校验文件及[公开发布页](https://github.com/fclx512/EUI-Edits/releases/tag/v0.1.0)一致，测试后再次校验未变。
- 源码核对基准：`5cbfa67e5b2ff3b905c6b5251bdc612aca4422fe`。测试过程中只修改文档和 Python 探针，没有重新编译或改动 EXE。
- 系统：Windows 11，`10.0.26300` / build 26300；Core Ultra 9 275HX；系统可见物理内存 33,784,107,008 字节（约 31.46 GiB）。
- 显卡清单：NVIDIA GeForce RTX 5070 Ti Laptop GPU（驱动 `32.0.16.1062`）、Intel Graphics（`32.0.101.8331`）；该清单不表示测试使用了硬件渲染，也不是 GPU 用量测量。
- 渲染：不向被测进程传入 `NEO_*` 实验覆盖变量。当前 Win32 版默认软件 Direct2D 与 DC 呈现，依据[后端初始化](../core/render/d2d/d2d_backend.cpp)确认；没有切换硬件路径。
- 窗口：外框固定为 1280 × 800 物理像素；有效场景客户区均为 1262 × 753 像素；DPI 120，即系统缩放 125%。没有调整驱动、注册表或系统内存策略。
- 设置：浅色内置主题，正文 16 / 界面 14，应用附加缩放 100%，简洁视图，自动换行、限制行宽、行号、状态栏和交互动画开启，使用预设系统字体。
- 每次启动单独隔离 APPDATA、TEMP 和 TMP；未打开主题、插件或图片。文档目录只有本次五个测试文件，目录扫描只涉及这些项目的元数据。

## 方法与统计口径

使用[复测探针](../tests/probes/readme_memory.py)生成可重复的测试文件。每个场景重新启动 3 次；小 Markdown 场景先打开三个标签，并逐页访问，使样本包含标签呈现缓存。窗口响应后静置 10 秒，再每隔 0.5 秒读取一次，保留 20 个样本。大文件场景在第 2 轮交换测量顺序。

通过 `GetProcessMemoryInfo` 的 `PROCESS_MEMORY_COUNTERS_EX2` 读取字节计数，原始值见[JSON 记录](measurements/memory-2026-10-05.json)。统计只取属于所启动 PID、保持前台、没有子进程、满 20 个样本且正常退出的运行。没有调用 `EmptyWorkingSet` 或强制收缩工作集，也没有手动触发垃圾回收。

| 名称 | API 字段 | 含义 |
| --- | --- | --- |
| 整体工作集 | `WorkingSetSize` | 当前驻留物理内存的进程可分页页面，包含可共享页面 |
| 专用工作集 | `PrivateWorkingSetSize` | 工作集中不可共享的部分 |
| 专用提交量 | `PrivateUsage` | 内存管理器已为进程提交的私有内存，不要求此刻全驻留 RAM |

定义来自[微软 EX2 文档](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters_ex2)及[工作集说明](https://learn.microsoft.com/en-us/windows/win32/memory/working-set)。三项不能相加；专用提交量也不是“当前占用的页面文件大小”。本记录统一使用 MiB，按字节数除以 1,048,576 换算；不要与十进制 MB 混用。

## 文件与场景

| 场景 | 打开的文件 | 文件字节数与行数 | 内容 / 操作 |
| --- | --- | --- | --- |
| 空白 | 未保存的空白页 | 0 字节，编辑器显示 1 行 | 1 个标签，无输入 |
| 小 Markdown | `small-1.md`、`small-2.md`、`small-3.md` | 各 860 字节、41 个文件行，合计 2,580 字节 | 中文正文、标题、任务列表、引用、代码块、表格、强调和行内代码；依次访问三页，最终停在第 3 页 |
| 大纯文本 | `large.txt` | 9,437,184 字节（9 MiB）、73,728 个文件行 | 每行 128 字节，包括末尾 LF；ASCII 前缀 `Text row: `，其余填充 `a` |
| 大 Markdown | `large.md` | 9,437,184 字节（9 MiB）、73,728 个文件行 | 每行 128 字节，包括末尾 LF；每行是列表项，含强调的 `bold` 和行内代码 `code`，其余填充 `a` |

“文件行”使用 Python `splitlines()` 计数，末尾 LF 不额外增加一条空文件行；编辑器将结尾空行也作为可编辑行，因此小文档状态栏显示 42 行，大文档显示 73,729 行。文件内容、名称、SHA256 都保存在 JSON 中，完整文件可由探针重新生成。没有对大文件滚动、编辑或保存。

## 结果

以下是三次运行各自 20 点采样中位数的中位数，单位 MiB：

| 场景 | 整体工作集 | 专用工作集 | 专用提交量 |
| --- | ---: | ---: | ---: |
| 空白 | 48.6 | 16.8 | 22.0 |
| 3 个小 Markdown 标签 | 57.8 | 23.4 | 32.2 |
| 9 MiB 纯文本 | 184.5 | 152.6 | 194.4 |
| 9 MiB Markdown | 306.6 | 274.5 | 322.1 |

各场景三次有效运行共 60 个样本的最小—最大值如下，单位 MiB；这只是所保留闲置样本的范围，不能当作进程生命周期峰值：

| 场景 | 整体工作集范围 | 专用工作集范围 | 专用提交量范围 |
| --- | ---: | ---: | ---: |
| 空白 | 48.27–49.08 | 16.52–16.86 | 20.94–22.17 |
| 3 个小 Markdown 标签 | 56.90–58.21 | 22.46–23.77 | 28.59–38.23 |
| 9 MiB 纯文本 | 184.02–184.65 | 152.10–152.73 | 193.21–195.11 |
| 9 MiB Markdown | 305.84–306.98 | 273.74–274.87 | 320.12–322.53 |

共 12 次有效运行、240 个采样点，进程数均为 1，全部通过 WM_CLOSE 正常退出，退出码为 0。另有一次大纯文本第 2 轮尝试中途丢失前台，窗口尺寸也变化；该尝试只取得 13 点，正常关闭后重新测量。原始记录保留其错误和样本，汇总明确排除，没有把失败尝试混入上述 240 点。

## 占用从哪里来

进程级计数没有记录每个组件的独立用量。下表是根据当前源码确认的来源类别，不能据此分摊实测 MiB 或推算百分比：

| 来源 | 源码依据与边界 |
| --- | --- |
| 窗口、字体、绘制缓冲和程序 / DLL 驻留页面 | [Direct2D 后端](../core/render/d2d/d2d_backend.cpp)创建绘制目标和资源；工作集含可共享页面。空白场景也有基础开销，无法用本次采样进一步拆分。 |
| 正文与编辑状态中的文本副本 | [Document 模型](../apps/neo_editor/model/text_file.h)使用 `std::string`，[活动文稿同步](../apps/neo_editor/state/app_state.h)保留文稿文本与编辑状态，[输入模型](../components/input_model.h)另有 `cachedLayoutText`。读取 / 解码可能产生临时缓冲；没有承诺每份文档只有一份正文副本。 |
| 行与光标度量、Markdown 解析 / 装饰、表格和高亮 | [输入模型](../components/input_model.h)缓存逐行排版、度量与光标位置；[标签缓存估算](../apps/neo_editor/state/document_tabs.cpp)计入解析计划、tokens 和呈现数据。大量行与复杂语法会增加派生结构，同一文件字节数不是同一内存成本。 |
| 撤销 / 重做 | [输入模型](../components/input_model.h)保存插入 / 删除区间文本，最多 128 条记录，没有字节总预算；大范围替换可能保留较大的记录。本次没有编辑，未测此类增量。 |
| 标签衍生缓存 | [标签缓存策略](../apps/neo_editor/state/document_tabs.cpp)默认按估算值保留至多 2 个非活跃页、64 MiB 衍生缓存；正文、撤销历史和活动资源不受该估算总额约束。预算不是进程工作集 / 提交上限。 |
| 文档库 | [目录项模型](../apps/neo_editor/model/vault.h)保留目录树、名称与路径等元数据；[目录缓存](../apps/neo_editor/state/vault_cache.cpp)有估算预算，但活动根不会被预算淘汰。它不预读目录中全部文件正文。 |
| 图片 | [图片解码](../core/render/image_source.cpp)将静态图像解码为 RGBA，像素字节数按宽 × 高 × 4 计算，另外还有呈现资源和引用。压缩后的图片文件大小不等于解码占用；缓存预算不约束所有仍被引用的资源。本次文档无图片，没有测图片增量。 |

本次等字节数、等文件行数的两份大文件，Markdown 整体工作集比纯文本约高 122.1 MiB。这只能说明这对具体样本在指定条件下存在差异；两者语法、字体段、可见换行和衍生结构不同，差值不能全部归为解析器，更不能推广为任意 Markdown 的固定倍数。

没有做组件级堆分析，也没有单独测量 GPU / 驱动用量、系统文件缓存、图片解码、长期编辑、保存峰值或内存压力下的行为。系统 DLL 的共享页面已经包含在整体工作集中，不能再把其差额与整体工作集相加。旧 README 的“9 MB 文本约 68 MB”没有可复核的行数和完整测试条件，本次取代该参考值，不据此声称版本回归或提升。

## 复测与本机证据

在 Windows、64 位 Python 和无其他 EUI-Edits 实例运行的条件下，从仓库根目录运行：

```powershell
python tests/probes/readme_memory.py `
  --exe out/euiedits-0.1.0-single-exe/EUI-Edits-0.1.0-windows-x64.exe `
  --out out/acceptance/readme-memory-new
```

默认即为 3 次启动、静置 10 秒、20 次采样、0.5 秒间隔。输出目录必须尚不存在；途中失败可用同样参数追加 `--resume`，探针核对 EXE、文件哈希和采样参数后保留失败记录并补测。复测会短暂置前测试窗口，操作前检查 PID 归属，不控制或关闭用户的其他进程。

本机证据目录为 `out/acceptance/readme-memory-20261005-r1/`，包括生成文件、每次隔离配置、程序日志、真实窗口截图和 `report.json`。每轮退出码、三种原始字节计数及无效尝试已复制到仓库中的[JSON 记录](measurements/memory-2026-10-05.json)；本机大文件与截图不纳入源码库。已查看四种场景的最终轮截图，确认空白页、三个已打开标签、大文本行数和 Markdown 呈现符合设定。
