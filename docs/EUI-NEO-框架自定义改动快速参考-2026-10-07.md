## 一页速览（按主题）

### 排版 / 字体（详见附录一）

- 文本排版对齐 CSS 口径（`core/render/text.cpp`，+1360 行）：字号即 em、行盒归一（ascent−descent=字号）、lineGap=0（默认行高=字号×1.2）、整数 ppem 光栅化 + hinted advance（修字符重叠/选区错位）。
- monospace 预设首选 Consolas（CascadiaMono 在该管线有渲染缺陷）；新增系统字体目录扫描兜底生僻字；缺字画豆腐块；新增 CJK 断行与统一断行决策；粗/斜体按文件解析不做合成体。
- 文本缓存大幅强化：双层度量缓存（TextMetrics 16MiB + Shaping 8MiB，O(1) LRU，`NEO_TEXT_CACHE_OFF` 可关）；字形图集 512 起步倍扩容 + 满页整页重置（修上游"图集满后永久缺字"）。
- 应用侧：界面字号全由 `uiFontSize`（默认 14）派生；Markdown 排版按 Obsidian 规格（行高 1.5、h1/h2/h3=1.618/1.462/1.318em）。

### 动画（详见附录一、三、四、五）

- `core/animation.h` 仅一处改动：平滑器 deltaSeconds=0 时不再瞬跳目标。
- 组件侧默认动画被普遍**关闭**：contextmenu 展开动画 0.12s OutCubic → `Transition::none()`；应用侧 `applyInteractionDefaults` 全树关动画（`NEO_FEEDBACK=0` 可开关）。
- 应用侧统一过渡 `quickTransition()` = 0.14s OutCubic（库默认 0.18s 且默认禁用）；toast 动态时长 2.6–12s；光标闪烁仅编辑器开启（0.53s 半周期）。
- 运行时配套：睡醒首帧动画 delta 截到 1/60s；纯边框动画只脏边框环带。

### 渲染后端（详见附录一）

- 新增整套实验性 **Direct2D 后端** `core/render/d2d/`（复用字形图集），`render_backend` 新增 frameReady/framePresented/supportsRetainedLayers 虚接口（D2D 返回 false 关闭 retained layer）。

### 窗口 / 主循环 / 平台（详见附录二）

- **主循环空闲模型**：上游无动画时 `glfwWaitEvents()`/SDL 100ms 轮询；本地改为 `nextTimerWakeSeconds()` 体系，睡到最近定时器/补帧到点，零 CPU 空闲。
- 新增**原生 Win32 窗口后端** `core/window/win32_backend.cpp`（Per-Monitor V2 DPI、IME 全套、WM_PAINT 补曝光条带、live resize WM_TIMER 延迟刷新），构建开关 `EUI_WINDOW_BACKEND_WIN32=1`。
- 尺寸变化 compose 节流（约 50ms 时间闸）；live resize 回调内限速直绘 + `NEO_LIVE_RESIZE=0` 逃生阀。

### 运行时 / 输入 / DSL（详见附录三）

- **定时器调度重写**（最大改动）：上游一次性定时器 + `animating_` 驱动全速渲染；本地改周期触发、只登记 `nextTimerWakeSeconds_` 供主循环带超时睡眠（省 14% 单核）。

- IME：新增 `cancelTextComposition()`（焦点切换/指针按下/禁用输入时取消组合）。

## 总体概述

本区域的自定义改动集中在四条主线：

1. **文本排版/字体度量对齐 CSS 口径**（`core/render/text.cpp`，改动最大的文件，+1360 行左右）：字号即 em、行盒归一、行高=字号（lineGap 归零）、整数 ppem 光栅化、hinted advance 取代 linearHoriAdvance、系统字体目录兜底扫描、豆腐块缺字兜底、CJK 断行、粗/斜体文件解析。默认字体不变（锦南君君体 + Font Awesome），但 monospace 预设把 Consolas 排到 Cascadia 之前。
2. **缓存策略大幅强化**：新增 T1 双层文本度量缓存（TextMetricsCache + ShapingCache，24 MiB 预算、O(1) LRU）、字体栈 fallback 指纹失效、灰度字形图集从 2048² 一次性预分配改为 512 起步按倍扩容 + 满页整页重置（epoch 机制），并新增 `debugAtlasStats()` 诊断接口。
3. **GPU 侧性能/稳定性**：删除了两处 `glFinish()`（resize 热路径）、新增 `gpu_resize_stats.h` / `resize_trace.h` 观测设施、整套实验性 Direct2D 后端 `core/render/d2d/`、`render_backend` 增加 frameReady/framePresented/supportsRetainedLayers 虚接口。
4. **动画与颜色插值的小而关键的语义修正**：`animation.h` 平滑器在 deltaSeconds=0 时不再瞬跳到目标；`render_types.h` 的 `mixColor` 改为预乘 alpha 空间插值，消除状态切换瞬间的闪灰。

`core/layout.h` 与上游**完全一致**（`--strip-trailing-cr` 后无差异），未做任何本地改动。

## core/animation.h

**改动点（~行 360-368，上游 ~行 359-366）：平滑动画器对 `deltaSeconds == 0` 的处理**

- 上游默认：`if (deltaSeconds <= 0.0f || speed <= 0.0f) { current_ = target; }` —— 帧间隔为 0（同帧内多次推进、批量输入等）时直接吸附到目标值。
- 本地改动：拆成两个条件 —— `speed <= 0` 才瞬跳；`deltaSeconds > 0` 才做指数插值；`deltaSeconds == 0` 时**保持当前插值不变**（附注释：零时长重组与批量输入必须保留当前混合状态，只有显式 instant 平滑才吸附目标）。
- 意图：修复零时间步动画被错误"瞬移完成"的问题（正确性修正，非默认参数调整）。

## core/render/text.cpp（改动最大的文件，1978 → 3337 行）

### 字体度量与排版参数（重点）

**1. 字号→em 换算改为"字号就是 em"（~行 1153-1180，上游 ~行 553-560）**
- 上游默认：`scaledFontSize = fontSize * upem/(ascender-descender)` —— 同字号下各字体视觉大小差可达 45%（微软雅黑 vs Consolas）。
- 本地：`scaledFontSize = fontSize`，直接对齐 CSS/浏览器口径（曾经历 1.30 固定基准的中间版本，因比别家小 30% 被废弃，2026-09-23 定稿）。意图：字体排版一致性。

**2. 行盒归一 + lineGap 归零（~行 1222-1240）**
- 上游默认：ascent/descent 用 FreeType 原始 `size->metrics`，lineGap = height − (ascent−descent)（字体设计值，雅黑 1.45em、Consolas 1.17em，换字体行距变）。
- 本地：ascender−descender 归一到恒等于字号（boxNorm 缩放）；**`face.lineGap = 0.0f`** —— 行高完全由调用方 lineHeight 决定（默认字号×1.2）。意图：跨字体行高一致。

**3. 整数 ppem 光栅化（~行 1200-1206）**
- 上游默认：`FT_Set_Char_Size` 用小数字号（DPI 1.25 × uiScale 步进产生大量小数 ppem），LIGHT hinting 字干落半像素。
- 本地：`rasterPpem = round(scaledFontSize)`，字号误差限 ±0.5px。意图：清晰度。

**4. advance 用 hinted `advance.x`，不再用 `linearHoriAdvance`（~行 1604-1618）**
- 上游默认：`FT_IS_SCALABLE` 时用 `linearHoriAdvance`（未 hint 的线性推进量）。
- 本地：删除该分支，一律用 hint 后的 `glyph->advance.x / 64`，与实际栅格化的字形一致（14px 下两者差 0.3px/字符，导致 Consolas 字符重叠、Cascadia 拉缝、选区错位）。注释明确：若将来改 NO_HINTING 须换回。意图：字体排版正确性。

**5. monospace 回退链把 Consolas 提到 Cascadia 之前（~行 957-966）**
- 上游默认顺序：CascadiaMono → CascadiaCode → consola → cour。
- 本地顺序：**consola.ttf 优先**。原因：CascadiaMono 是可变字体，本管线（整数 ppem + LIGHT hinting）渲染它标点缩小下沉。意图：字体默认观感。

**6. 系统字体目录兜底扫描（新增 ~行 1409-1500 `scanSystemFontsForCodepoint`，挂入 `findFaceForCodepoint` ~行 1532-1540）**
- 上游默认：既定栈与回退链都缺码点时直接返回 face 0（画不出/空白）。
- 本地（Windows）：扫 `C:/Windows/Fonts` 全部 ttf/ttc/otf 找第一份含该字形的字体挂进栈，结果按码点全局备忘（一次目录扫描跨字号复用）。意图：fallback 字体覆盖面（生僻字/符号）。

**7. 豆腐块兜底 `rasterizeTofuGlyph`（新增 ~行 2622-2665；接入点 ~行 2522-2560、~行 2548）**
- 上游默认：码点缺字形或 `FT_Load_Glyph` 失败时缓存**空字形**（渲染为空白）。
- 本地：合成描边豆腐块（宽 0.58em、高 0.64em、描边 ≥2 逻辑 px）放入灰度图集，同字号共用一枚；另对超大位图（>4096 边或 >4M 像素）也回落豆腐。意图：缺字可见性。

**8. CJK 断行与统一断行决策 `wrapLineStarts` / `isCjkBreakCodepoint` / `lineInkEnd`（新增 ~行 2128-2230）**
- 上游默认：渲染（rebuildLayout）与度量（measureTextSize）各自独立做贪心换行，只认空格断词；CJK 无空格文本无法断行。
- 本地：抽出唯一断行决策函数（空格/CJK 码点缝隙、行尾空白丢弃、无缝硬断兜底），渲染与度量共用同一实现，保证行数/行宽一致。意图：CJK 排版正确性。

**9. 粗体文件解析 `resolveBoldFontPath` + `resolveFontPath` 重构（新增 ~行 2896-3060）**
- 上游默认：`fontWeight >= 600` 时 `resolveFontPath` 返回 `resolveDefaultUiFontPath()`（实际等于换默认字体，且 fontWeight 只参与缓存键、不改变渲染）。
- 本地：按命名约定找同族真粗体文件（X.ttf → X-Bold/-Bold/SemiBold/bd…；雅黑→msyhbd.ttc；黑体/宋体回落常规；斜体文件先找粗斜体 bi/BoldItalic），用 FreeType 验证；找不到回落常规。意图：字重真正生效，不做合成粗体。

### 缓存策略（重点）

**10. T1 双层文本度量缓存（新增 ~行 104-475 + 测量路径接入 ~行 2128-2200 + extern "C" 测试钩子 ~行 3260-3350）**
- 上游默认：只有字体栈缓存（16 格）与 TextSizeCache（1024 格），塑形每帧重复执行；ShapingCache 淘汰是 O(n) `min_element` 全表扫。
- 本地新增两层：
  - 内层 **ShapingCache**（键 = holder 指针 + 文本，2048 条 / 8 MiB，weak_ptr 随 holder 失效，O(1) 侵入式 LRU）；
  - 外层 **TextMetricsCache**（键 = 实际字体路径 + 字号 + 文本，65536 条 / 16 MiB；快路径命中直接返回，不碰 FreeType 不 shape）。
  - 共用一把 `std::recursive_mutex textCacheMutex()`（上游各缓存各自为政、无统一锁；本地顺带修复了 `setDefaultFontFiles` 写 override 与读侧的 data race）；`NEO_TEXT_CACHE_OFF=1` 可整体关闭跑基线。
- 意图：性能（编辑器全文档塑形是 resize 卡顿大头）+ 缓存有界性 + 线程安全。

**11. 字体栈 fallback 条目文件指纹失效（~行 175-205、~行 1256-1290、~行 1348-1356）**
- 上游默认：字体栈缓存条目永不校验请求路径的文件是否后来变得可用。
- 本地：fallback 条目（请求字体没成为首面时）记录请求路径的 存在性+size+mtime 指纹，下次命中比对，变了即丢弃重载；正常条目零额外 syscall。意图：字体热替换正确性。

**12. 灰度图集：2048² 预分配 → 512 起步按倍扩容（~行 45-46、~行 684-760、~行 825）**
- 上游默认：`kGrayAtlasSize = 2048`，`retainSharedTextAtlas` 一次性分配 2048² 灰度页（4 MiB）；页满后静默缓存空字形。
- 本地：`kGrayAtlasInitialSize = 512`、`kGrayAtlasMaxSize = 2048`；新增 `growGrayAtlasPage()`（倍增拷贝、UV 重基、纪元+1）、`appendGrayGlyph()`（先塞、再扩、最后整页重置）；`NEO_GRAY_ATLAS_INITIAL_SIZE=2048` 环境变量可还原上游脚印。意图：内存脚印（小文档不再预付 4 MiB）+ 缓存策略。

## 总体概述

本项目在"应用宿主 / 窗口 / 平台"三层对上游默认行为做了系统性的自定义，主线有五条：

1. **按需渲染 + 定时器唤醒的空闲模型**：上游主循环在无动画时只做 `glfwWaitEvents()`（无限期等事件），定时器只能靠持续轮询/渲染等时间。本地补齐了 `nextTimerWakeSeconds()` 体系（app.h / dsl_app_impl.h / dsl_window_manager.h / dsl_window_runtime.h / main_window_runtime.h），主循环"睡到最近一个 pending 定时器到点"，没有定时器才无限期等事件，实现真正的零 CPU 空闲。
2. **live resize 拖拽期渲染策略**：新增 `ResizeComposeThrottle`（dsl_window_runtime.h），把"纯尺寸变化"触发的整树 compose 节流到约 50ms 一次（跳过的 tick 不写 composed 尺寸、只挂账，主循环定时补终态帧）；配合 Win32 后端的 WM_TIMER 延迟刷新，把拖拽期的重绘调度到显示器刷新预算内。可用环境变量 `NEO_LIVE_RESIZE=0` 关闭。
3. **原生 Win32 窗口后端（绕过 GLFW/SDL）**：新增 `core/window/win32_backend.cpp` + `win32_host.h`，直接实现 window_backend 抽象（WM_PAINT/WM_SIZE/IME/WM_DPICHANGED/WM_GETMINMAXINFO 全套），构建开关 `EUI_WINDOW_BACKEND_WIN32=1`。桌面入口重构为共享的 `desktop_app_main.inl`，按宏在 Win32 宿主与 GLFW 宿主（薄封装 `glfw_host.h`）之间二选一；`glfw_app_main.cpp`、`win32_app_main.cpp` 都退化为一行 include。
4. **DPI 与路径的 Unicode 化**：Win32 后端声明 Per-Monitor V2 DPI 感知、按窗口 DPI 换算 min/max 尺寸与初始尺寸；platform.cpp 把 `GetModuleFileNameA` 换成 W 版（中文/Unicode 路径可执行文件目录），托盘图标路径走 UTF-8（`fs::u8path` / `u8string`），tray_bridge.c 用宏适配第三方 tray.h 的 `ExtractIconEx` 为 UTF-8 版本。
5. **应用生命周期与资源内嵌**：新增单实例闸门 `app::singleInstanceGate()`、可否决的关闭请求 `requestClose/consumeCloseRequest/allowCloseRequest`、DSL 配置项 `interactiveCursor`（可点元素光标可改）与 `onCloseRequest`；新增 `core/platform/bundled_resources.cpp/.h` 从 EXE 的 RCDATA 资源读取许可证文本/图标，支持 `--export-licenses` 命令行与"另存为"导出对话框。

另有若干小修：文件对话框归属 owner 窗口 + `OFN_NOCHANGEDIR`、过滤器超 8 个扩展名时省略括号清单、"All files" 改中文、渲染帧 `frameReady/framePresented` 失败重试（防丢帧挂死外观）、重复帧重入保护（FrameGuard）等。

## 总体概述

本区域的自定义改动围绕三条主线展开，全部服务于"把上游通用 UI 库改造成一个可长期运行、按需重绘的文本编辑器（NeoEditor）宿主"：

1. **按需重绘调度（最大的改动面）**：上游的定时器靠"置 animating_ 让应用持续全速渲染"来等时间；本地改成定时器只登记"下次唤醒剩余秒数"（`nextTimerWakeSeconds_`），由主循环带超时地睡眠等待。配套改动包括：悬停光标只在有指针事件的帧重置、动画在"从睡眠中醒来"的首帧用小步长补间、纯边框动画只脏边框环带、滚动视口脏矩形改为"变换后的真实视口"并延迟到指针事件处理完再 flush。
2. **IME / 文本输入语义**：新增 `cancelTextComposition()`，在焦点切换、指针按下、输入禁用、shutdown 时主动取消原生 IME 组合窗口并消费残留文本；新增 `TextInputEvent::pasteRequested`（Ctrl+V 到达但剪贴板无文本时置位，宿主可借此尝试图片粘贴）；跟踪 `composingText_` 状态。
3. **光标与坐标语义**：`CursorShape` 新增 `IBeam`；元素新增 `cursorAt()` 回调（按悬停点动态返回光标形状）；Hand 光标改为"可点元素"的抽象标记，实际形状由 `Runtime::setInteractiveCursor()` 映射；所有指针回调（onPress/onRelease/onDrag/cursorAt）收到的坐标从设备像素改为**逻辑坐标**（除以 dpiScale）。

另有零散改动：DSL 新增 `requestFocus()`（组合期申请焦点，运行时校验后应用）；渲染层 retained layer 增加后端能力门控（`supportsRetainedLayers`，D2D 后端返回 false）；滚动状态绑定区分"组合给出的受控偏移"与"回调回声"。

## 1. core/runtime/runtime_input.h

### 1.1 焦点切换时冲刷残留文本输入并取消 IME 组合（约 L232–238、L258–272）

- **上游默认**：`setFocusedId(id)` 直接切换 `focusedId_`，旧控件的 IME 组合/已提交文本不做任何处理；没有 `cancelTextComposition` 这个函数。
- **本地改动**：切换焦点前，若 `inputWindow_` 非空且还有未消费的 `TextInputEvent`，先 `consumeTextInput` + `updateTextInput` 把文本记到旧控件账上；然后调用新函数 `cancelTextComposition()`。新函数查询原生窗口 IME 组合状态（`queryImeComposition`），若正在组合则调用 `core::window::cancelImeComposition()` 取消，并派发一个仅含 `compositionChanged=true` 的 `TextInputEvent` 让旧控件清理下划线等组合态。
- **意图**：IME 正确性——组合中的文本/拼音候选必须归属于触发焦点切换前的那个控件，防止"焦点已切走、拼音却打进新控件"。

### 1.2 updateTextInput 记录组合状态（约 L297）

- **上游默认**：无 `composingText_` 跟踪。
- **本地改动**：`composingText_ = event.composing || !event.compositionText.empty();`，供 `cancelTextComposition()` 判断是否需要取消。

### 1.3 悬停光标：wantsHandCursor_ → hoverCursor_ + cursorAt 动态光标（约 L412–421）

- **上游默认**：仅当元素 `cursor == CursorShape::Hand` 且处于悬停时置 `wantsHandCursor_ = true`；每帧无条件清零。
- **本地改动**：条件放宽为 `element.cursorAt || element.cursor != CursorShape::Arrow`；若有 `cursorAt` 回调，则把事件坐标换算成逻辑坐标后调用 `cursorAt(logicalEvent, toLogicalRect(interactionBounds, dpiScale))` 动态决定光标形状（如文本编辑区内按位置区分 IBeam/Hand），否则用静态 `element.cursor`，结果存入 `hoverCursor_`。
- **意图**：命中测试/光标语义增强——同一元素内部不同区域可有不同光标（编辑器文本区典型需求）。

### 1.4 指针回调收到逻辑坐标（约 L489–495、L506–512、L540–546）

- **上游默认**：`element.onPress/onRelease/onDrag` 直接收到设备像素坐标的 `PointerEvent` 和设备像素 `interactionBounds`（onDrag 里的 x/y/delta/dragDelta 全是原始值）。
- **本地改动**：三处回调均先构造 `logicalEvent`，将 `x/y/deltaX/deltaY`（onDrag 还包括 `dragDeltaX/dragDeltaY`）除以 `dpiScale`，并把 bounds 经 `toLogicalRect(interactionBounds, dpiScale)` 转为逻辑矩形后再传入。onDrag 改为就地展开构造 `DragEvent`。
- **意图**：统一坐标系语义——用户回调一律使用逻辑（DIP）坐标，与 DSL 布局坐标一致，免去每个回调自己除 DPI。**这是对所有复用者可见的破坏性 API 语义变更。**

- **意图**：同 2.2，把"用户按了粘贴键"这一事件从"剪贴板里恰好有文本"中解耦。

## 4. core/runtime/runtime_lifecycle.h

### 4.1 Runtime 记录 inputWindow_（约 L10、L60、L295–297）

- **上游默认**：`Runtime` 不保存 window 句柄，所有输入函数都靠参数传 window。
- **本地改动**：`initialize/update` 时记录 `inputWindow_ = window`；`shutdown()` 时先 `cancelTextComposition()` 再置空。供 `setFocusedId`/`cancelTextComposition` 在无 window 参数的上下文中访问原生 IME。

### 4.2 组合结束后消费 DSL requestFocus（约 L24–30）

- **上游默认**：`compose()` 后只收集元素结构、同步滚动绑定；焦点只能由指针点击或 `setFocusedId` 改变，DSL 层没有焦点申请通道。
- **本地改动**：compose 后调用 `ui_.consumeFocusRequest(requestedFocus)`（见第 8 节 dsl.h），目标存在、`focusable` 且不在禁用子树内时调用 `setFocusedId()`。`syncScrollStateBindings` 改为传 `true`（组合期接受受控偏移，见第 6/7 节）。
- **意图**：声明式焦点管理——例如打开对话框/新建标签后自动聚焦输入框。

### 4.3 输入禁用帧取消 IME 组合（约 L66）

- **上游默认**：`!inputEnabled` 时仅 `cancelInput(window)`（清指针/按键队列）。
- **本地改动**：额外调用 `cancelTextComposition()`。

### 4.4 悬停光标只在有指针事件的帧重置（约 L86–95）★默认行为改变

- **上游默认**：每帧 `wantsHandCursor_ = false`（配合上游"持续渲染"模型没问题）。
- **本地改动**：先 `nextTimerWakeSeconds_ = +inf` 复位定时器唤醒登记；然后仅当 `!pointerEvents.empty()` 才把 `hoverCursor_` 清回 `Arrow`。注释明说：按需渲染下定时器/后台唤醒的帧没有指针事件，若照旧每帧重置，`applyCursor` 会在鼠标静止时把 I-beam 打回箭头（"编辑器停住不动一个闪烁周期就变回箭头"）。
- **意图**：按需重绘调度与光标状态的兼容——光标是粘性状态，只能由指针移动/布局变化刷新。

### 4.5 指针按下前冲刷文本输入并取消组合（约 L114–121）

- **上游默认**：指针事件循环里直接 `setFocusedId(hitTestFocusable(...))`。
- **本地改动**：任何左/右键 press 事件前，若本轮已有 `textInputEvent` 先 `updateTextInput` 落账，再 `cancelTextComposition()`（注释：候选窗口点击是原生的，不进客户端指针队列）。
- **意图**：点击移动插入点/换控件前，IME 组合与已提交文本必须先归属旧焦点。

### 4.6 滚动脏矩形延迟 flush（约 L131）

- **上游默认**：无 `flushPendingScrollDirtyRects`。
- **本地改动**：指针事件循环结束后调用 `flushPendingScrollDirtyRects()`（实现见第 7 节 runtime_update.h）。
- **意图**：保证同帧内滚动偏移变化（含受控绑定回写）产生的视口脏矩形在 `updateDependentVisualDirtyRegions` 前全部入账。

### 4.7 新增 nextTimerWakeSeconds() 查询（约 L161–163）

- **上游默认**：无。上游定时器靠 `animating_` 驱动持续渲染。
- **本地改动**：暴露 `nextTimerWakeSeconds()`，返回 `nextTimerWakeSeconds_`（+inf 表示无定时器），dsl_runtime.h 同步暴露（见第 9 节）。主循环据此做带超时的事件等待。
- **意图**：按需重绘调度的核心接口——定时器不再是动画。

### 4.8 applyCursor 重写：IBeam + interactiveCursor_ 映射（约 L318–338）★默认行为改变

- **上游默认**：`wantsHandCursor_` 为真就用 Hand 光标，否则 Arrow；Hand 光标惰性创建。
- **本地改动**：`hoverCursor_ == Hand` 时实际形状取 `interactiveCursor_`（默认 `Hand`，可经 `Runtime::setInteractiveCursor()` 改，如改成 IBeam 让所有"可点"元素显示 I 型）；`hoverCursor_ == IBeam` 直接用 IBeam 光标（惰性创建 `ibeamCursor_`）；各光标句柄判空后再用，回退 Arrow。释放资源时新增销毁 `ibeamCursor_`（约 L350–353）。
- **意图**：把"可点"（Hand，语义标记）与"实际画什么"（interactiveCursor_）解耦，并原生支持文本 IBeam。

## 6. core/runtime/runtime_state_bindings.h

### 6.1 syncOwnedScrollState 支持受控偏移回写（约 L87–120）★默认行为改变

- **上游默认**：签名 `syncOwnedScrollState(element, instance)`；初始化时 clamp `element.scrollOffset` 一次性采纳，此后只做 `instance.offset = clamp(instance.offset, ...)` 的越界收敛——即滚动偏移是运行时独占的"非受控"状态，组合层写的 `scrollOffset` 只在首帧生效。
- **本地改动**：签名改为 `syncOwnedScrollState(element, instance, bool acceptBoundOffset)`，返回 `bool offsetChanged`。当 `acceptBoundOffset`（组合期传 true）且组合给的 `element.scrollOffset` 与活动 offset 不同，则采纳组合值并**清零惯性速度**（`velocity = 0`）；否则维持上游的 clamp 收敛行为（收敛时也返回 offsetChanged 并清速度）。同时视口脏矩形不再在这里赋值（上游此处设 `instance.dirtyRect = element.frame`），改由 update 树按变换后视口写（见 7.3）。
- **意图**：状态绑定语义——支持"受控滚动"（应用持有权威 offset，每次 compose 回写，如代码折叠/同步滚动）；回调回声等于活动值时不会打断进行中的惯性动画。脏矩形改为精确视口也是为了按需重绘下擦除正确。

### 6.2 新增 scrollViewportDamageRect（约 L122–126）

- **上游默认**：无。
- **本地改动**：`scrollViewportDamageRect(frame, dpiScale, effectiveTransform)` = `applyRenderTransformToLogicalRect(...)`，把元素 frame 经有效渲染变换映射为脏矩形。

## 7. core/runtime/runtime_update.h

### 7.1 定时器：周期化 + 余数保持 + 不再驱动持续渲染（约 L387–408）★最大的默认行为改变

- **上游默认**：`updateTimer` 中计时到点后 `instance.active = false`（**一次性定时器**）、触发 `onTimer`、置 `composeRequested_/paintRequested_`；未到点则置 `animating_ = true`（**靠全速渲染循环等时间**）。且上游在新建 timer 的那一帧就把当帧 delta 计入 elapsed（首帧可能吞进之前长闲置/模态对话框的时长）。
- **本地改动**：
  - 新建帧**不**累加 delta（else 分支才加），避免首帧吞时；
  - 到点后 `elapsed = fmod(elapsed, seconds)` **保留余数**（周期定时器不逐帧漂移），且不清 `active`（周期性重复触发）;
  - **不再置 `animating_`**，改为 `nextTimerWakeSeconds_ = min(..., remaining)` 登记"还有多久要醒"。
  - 注释明说动机：上游方式让 1MB 文档的编辑器"常年吃掉 14% 的单核"。
- **意图**：按需重绘调度。**复用提示**：依赖上游"timer 触发后变一次性、需手动重启"或依赖"timer 期间 animating()==true"的行为会破坏。

### 7.2 syncScrollStateElement 回调 onScrollOffsetChanged + 按需脏矩形（约 L420–437）

- **上游默认**：只调 `syncOwnedScrollState(element, instance)`，不同步回调、不产生脏矩形。
- **本地改动**：`syncOwnedScrollState` 返回 offsetChanged 时 `addScrollDirtyRect(element.scrollStateId, instance)`；且当 clamp 后的组合偏移与元素记录值不一致时触发 `element.onScrollOffsetChanged(instance.offset)`（受控回写通知）。
- **意图**：受控滚动绑定生效路径（配套 6.1 与 4.2 的 `syncScrollStateBindings(true)`）。

### 7.3 addScrollDirtyRect 去重排队 + flushPendingScrollDirtyRects（约 L467–490）

- **上游默认**：`addScrollDirtyRect(instance)` 直接 `addDirtyRect(instance.dirtyRect)`（脏矩形是元素 frame）。
- **本地改动**：改为 `addScrollDirtyRect(stateId, instance)`——把 stateId 排入 `pendingScrollDamageIds_`（去重）；新增 `flushPendingScrollDirtyRects()` 统一把各滚动实例的 `dirtyRect`（现在是 7.4 的**变换后视口矩形**）加入脏区。`syncScrollUpdate`（约 L508）同步改用新签名。
- **意图**：滚动脏矩形必须等 update 树算出最终视口（含祖先变换）后再入账；去重避免同帧多次重复入账。

### 7.4 updateElementTree 写入变换后滚动视口脏矩形（约 L693–700）

- **上游默认**：无此逻辑（视口矩形在 6.1 上游版里是元素 frame）。
- **本地改动**：`ownsScrollState(element)` 时用本元素 `renderTransform` 调 `scrollViewportDamageRect()` 写入 `scroll.dirtyRect`。
- **意图**：按需重绘正确性——"sparse/transparent rows must still erase the whole prior viewport"，注释明确脏矩形是变换后视口而非内容边界估计。

### 7.5 睡醒首帧动画小步长 visualDeltaSeconds（约 L674–690）★默认行为改变

- **上游默认**：所有元素视觉更新一律用真实 `deltaSeconds`。
- **本地改动**：`previousFrameAnimating_` 为假（即刚从按需睡眠中醒来）时，布局/矩形/多边形/文本/图片更新的 delta 收敛为 `min(deltaSeconds, 1/60s)`；Shadertoy 与 timer/onFrame 仍用真实 delta。注释：睡眠期间没有动画，醒来首帧视觉运动从一小步开始；已在跑的动画时钟不受影响。
- **意图**：防止长空闲后醒来一帧动画跳变/瞬移。

### 7.6 纯边框动画的窄带脏矩形优化（约 L842–880）★默认行为改变

- **上游默认**：任何动画属性变化都 `addDirtyUnion(beforeRect, afterRect)` 全量前后矩形并集。
- **本地改动**：属性 tick 拆成逐项布尔；当**仅** `borderChanged`（颜色/粗细）且 `blur <= 0` 时，不加并集，改为只脏边框环带（上下左右四条，带宽 = border.width + 2px）。注释：编辑器输入区覆盖全文档的大矩形聚焦边框渐变由此不再逐帧全量重绘。
- **意图**：按需重绘的脏区最小化。

## 总体概述

`components/` 下 39 个同名头文件中**只有 6 个被修改**：`contextmenu.h`、`dialog.h`、`input.h`、
`input_model.h`、`markdown.h`、`toast.h`。此前任务假设有差异的 `theme.h`、`text.h`、`scroll.h`、
`layout_debug.h`、`workshop/` **与上游逐字一致**——即主题 token、度量 token、动画 token 本身没有被
改，所有默认值定制都发生在**组件各自的 builder 默认值和布局公式**里。

本地新增 3 个头文件：`input_line_map.h`（编辑器投影/几何纯逻辑层）、`text_wrap.h`（通用换行）、
`vector_icon.h`（纯矢量图标）。

改动的主线非常明确：**把上游"通用 UI 组件库"向 Obsidian 风格的 Markdown 编辑器（NeoEditor /
Live Preview）深度特化**——

1. `input.h + input_model.h + input_line_map.h` 三件套从"单行/多行文本框"重写为富文本编辑器内核：
   逐行装饰（字号/行高/隐藏区间）、行内样式段、行号列、代码块底色、引用竖条、表格网格线、块级图片、
   折叠、光标闪烁、横向滚动。
2. `markdown.h` 加虚拟滚动、可配置标题/代码行高、修 CJK 字间距、缓存扩容 64 倍。
3. `toast.h / dialog.h / contextmenu.h` 重排默认几何（间距从 metrics token 改为实测/固定值）、
   增加自适应尺寸与更多 builder 钩子；contextmenu 默认动画被关闭。

复用提示：主题/度量/动画 token 全在上游原样的 `theme.h` 里；若要沿用本项目的观感，重点抄下面

## 总体概述

neo_editor 对 UI 库的定制分三个层次：

1. **启动配置层**（`app.cpp` 的 `dslAppConfig()`）：通过 `DslAppConfig`（`include/eui/dsl_app.h:13`）一次性覆盖窗口尺寸/底色/全局字体/UI 缩放/帧率/光标形状/按键钩子。这是"框架级"的显式入口，应用保留了 `neo::mutableAppConfig()`（`app.cpp:789`）这个可写引用做运行时改写。
2. **主题令牌层**（`model/style_schema.h`）：应用不直接用库的 `components::theme::light()/dark()` 产出物，而是自建一套 32 字段的语义配色 `EditorColors`（`makeColors()`），再把它**反灌进库的 `ThemeColorTokens`**（`deriveThemeTokens()`），然后每个库组件（dialog/toast/contextMenu/input/button/virtualList/scrollbar…）都显式传 `.theme(colors.tokens)`。
3. **逐控件覆盖层**（`ui/`、`ui/editor_view.h`）：对 input、MarkdownStyle、virtualList、toast 等库组件逐一改默认值（圆角、内缩、行高、动画时长、滚动步长等）。

另有一条贯穿性的设计：**所有界面字号/尺寸从 `state.uiFontSize` 派生**（`ui/metrics.h` 的 `uiMetrics()`），动画有一个全局总开关（`applyInteractionDefaults`），主题/字体运行时可换且带版本号缓存。

## 2. 字体与排版

### 2.1 全局界面字体

- 位置：`apps/neo_editor/app.cpp:61-68`（`defaultTextFont()`）与 `app.cpp:432-434`。
- 库默认：框架自带默认字体（Bold 显示体，`assets/icon.png` 同级的内置字体），`DslAppConfig::textFontFileValue` 缺省为空（`dsl_app.h:46`）。
- 应用覆盖：Windows 上全局字体 = `C:/Windows/Fonts/msyh.ttc`（微软雅黑）；用户在设置里选过字体则用 `state.uiFontFile`。注释特别说明：**必须走 config 传**——框架 `initialize()` 会用配置值覆盖一次全局字体，启动时直接调 `setDefaultFontFiles` 会被盖掉（运行时换字体才走 `core::TextPrimitive::setDefaultFontFiles(uiFontFamily(state), "")`，见 `state/app_actions.cpp:1516、1604`）。
- 预设名兜底：`kUiFontFamily = "Microsoft YaHei"`（`style_schema.h:27`）——界面每处 `ui.text()` 显式传的字体名（`uiFontFamily(state)`，`state/app_state.h:452-454`）；库组件内部文字（按钮/对话框/下拉）靠全局默认字体，由 `applyUiFontFile()` 一并换掉。
- 作用范围：全局；换字体后调 `app::detail::requestFullPaint()` 作废保留层旧字形（`app_actions.cpp:1517-1519`）。

### 2.2 编辑区字体 / 等宽代码字体与 fallback

- 位置：`model/style_schema.h:441-452`、`state/app_state.h:459-468`、`platform/font_safety.h`、`model/font_catalog.h`。
- 覆盖逻辑：
  - 编辑区/预览：自选字体文件 > `kUiFontFamily`（雅黑）。框架对"含 `.` 的字符串"直接按文件路径加载（`core/render/text.cpp:1850` 附近）。
  - 代码块/行内代码/源码视图：自选等宽文件 > `"monospace"` 预设；库把该名解析为系统等宽字体，Windows 顺序 **Consolas 优先于 Cascadia Mono/Code**（`core/render/text.cpp:960-968`：CascadiaMono 是可变字体，标点观感差）。注释强调等宽是代码块的默认而非可选项。
  - 主题文件里的 `bodyFontFamily/codeFontFamily` 只是"建议值"：仅当调用方还在用预设名（= 用户没自选）时才采纳（`style_schema.h:398-409`）。
- 安全网：自选字体启动前经 `fontsafety::validate()`（隔离辅助进程、4s 超时，`platform/font_safety.h:22`）；代码字体额外要求真等宽；会话崩溃恢复标记（`armSession/recoverSession`）保证坏字体回退预设并提示（`app.cpp:114-139`）。
- 字体枚举：`model/font_catalog.cpp` 扫描 `%WINDIR%\Fonts` 与 `%LOCALAPPDATA%\...`，解析 name 表取族名、post/OS2 取等宽提示。

### 2.3 字号体系

- 位置：`state/app_state.h:38-52`（常量）、`ui/metrics.h:21-94`（派生）。
- 应用默认与范围：
  - 编辑区字号 `kDefaultEditorFontSize = 16`，范围 12–32（`app_actions.cpp:1426` clamp）。
  - 界面字号 `kDefaultUiFontSize = 14`，范围 12–18（18 是实测设置面板手排行高 46px 的上限，见 `app_state.h:47-49` 注释）。库 TypographyTokens 对应档位 label=14/body=16（`components/theme.h:9-32`）。
- 派生规则（`uiMetrics()`，全部逻辑像素，框架再乘 effectiveScale）：菜单栏高 `max(30, ui+20)`、菜单项高 `max(28, ui+18)`、状态栏 `max(24, ui+12)`、侧栏行高 `max(22, round(ui×1.85))`（必须固定值——virtualList 等高行前提）、状态/侧栏字号 `ui-1`、设置面板标题 `ui+4`、页面大标题 `ui×2`。结构体里字面量只是派生失败兜底。

### 2.4 Markdown 排版参数（Obsidian 规格）

- 位置：`model/style_schema.h:92-97`（默认倍率常量）、`style_schema.h:376-435`（`markdownStyle()` 现算）。
- 库默认：`components/markdown.h:29-50` —— body 16、bodyLineHeight 24、h1 30/h2 24/h3 20、code 14、blockGap 12、listIndent 22、radius 6、headingSpaceBefore 16。
- 应用覆盖（Obsidian 默认主题实测比例，全部从编辑区字号 em 派生，改字号观感不变）：
  - 正文行高 `1.5×`；段间距 `1.0em`；列表缩进 `1.625em`；代码块圆角 `0.25em`（4px@16）；代码字号 `0.875×`、代码行高 `1.5×代码字号`。
  - 标题字号 h1/h2/h3 = `1.618/1.462/1.318em`；标题行盒 `1.2×字号 + 1em` 上方留白（近似 Obsidian 的 16px heading-spacing）；h3 文本行盒例外用 1.3；`headingSpaceBefore/tableSpaceBefore` 各 `1.0em`。
  - v2 主题文件可覆盖以上倍率与正文字体；**标题行盒的 +1em 留白不开放主题覆盖**（`style_schema.h:418-423`）。
- 作用范围：编辑区 Live Preview（`ui/editor_view.h:41-43` 传入 `state.editorFontSize` + 字体）及装饰层（`lp::cachedDecorationSnapshot`）。

### 2.5 缩放（DPI）

- 位置：`app.cpp:411-435`、`state/app_actions.cpp:1419-1426`（`applyUiScale`）、`state/document_tabs.cpp:506-507`。
- 机制：框架 `effectiveScale = dpiScale × uiScale`。应用 `uiScale` 默认 1.0（= 跟随系统），范围 0.80–2.00、步进 0.05（`app_state.h:39-42`）。窗口物理尺寸按系统缩放预乘：`windowSize(scaled(896), scaled(608))`、`minWindowSize(scaled(608), scaled(384))`——保证不同系统缩放下"可见文字量"一致。
- 运行时改缩放：框架每帧从配置读 uiScale，应用直接写 `mutableAppConfig().uiScaleValue`（`app_actions.cpp:1424`）+ requestUpdate。
- 系统缩放在 GLFW 初始化**之后**才问（`neo::dialogs::systemScale()`，`app.cpp:168-170`），否则永远拿到 100%。
