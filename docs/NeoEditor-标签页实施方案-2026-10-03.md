# 标签页实施方案

日期：2026-10-03。状态：用户后续授权实现，第一版已落地。范围按用户图二：标签放在文件／编辑／视图菜单右侧，与菜单共用一行；采用浏览器圆角卡片。保存内存和输入框修复另行记录，性能专项继续后置。实现契约见[标签页技术说明](NeoEditor-标签页状态与恢复技术说明-2026-10-03.md)。以下保留设计依据。

## 外观与窄窗口

文档库模式的标签起点为 `max(菜单末端 + 12, 侧栏实际宽度 + 分隔线)`；简洁模式从菜单末端开始。使用实际布局宽度，而非图中的固定 x=324。现有菜单行高为 `max(30, UI字号+20)`，卡片顶部留 4、底部连正文，顶部圆角 7–9 逻辑像素。活动页使用编辑区底色，其他页使用菜单栏近似底色和轻分隔；悬停轻微提亮，保持既有原生矢量风格。

卡片包含文件类型图标、文件名、省略号、修改圆点和关闭按钮。正常宽度约 150–210，最小约 110；单个标签也显示。标签区域右端扣除现有设置入口及窗口控件占用，再保留新建按钮和标签列表入口。装不下时使用横向滚动和列表，自动露出活动页，不把文字与关闭按钮压成无法点击的尺寸。极窄窗口只显示活动卡片和标签列表；菜单优先，仍不增加一整行。关闭按钮命中区建议至少 24×24。

示意（文字代表信息层级，非最终像素稿）：

```text
文件  编辑  视图       ╭──────────────────╮ ╭──────────────────╮  ＋  ▾
                      │ MD 说明.md  ●  × │ │ TXT 日志.txt   × │
──────────────────────╯                  ╰─┴──────────────────┴────────
文档库侧栏            当前标签正文
```

## 跨文档库：每个标签保存上下文

建议采用「活动标签决定当前侧栏」。打开库 A 的文件，再打开库 B 的文件后，切回 A 会恢复 A 的根、展开目录、筛选、滚动和选中项。颜色只帮助辨认，不能决定路径、附件保存目录或文件操作目标。

已纳入用户追加规则：现有标签的库根存在父子包含关系时，统一使用其中最短的已打开祖先根。`BallonsTranslator-lite/docs` 与 `BallonsTranslator-lite` 合并为后者；展开路径及选中项重新换算为新根下的相对路径。无关根保持独立，不自动推算盘符或多个兄弟目录的公共祖先。库树以圆点标记所有已打开文件，折叠目录也提示其中有打开的文稿；活动文件另保留选中条。关闭父目录文稿后不自动缩小已合并根。

根选择沿用当前行为并明确化：从库树打开文件继承该库根；从外部打开、命令行或最近文件打开时，若文件属于当前库则继承，否则以文件父目录为根。手动选择目录只改变当前标签的库上下文；新建页继承当前根；从简洁模式打开无库的新文稿可保持空根。另存为落在原库外时跟随新父目录，库内另存仍保持根。所有根判断使用规范化路径及组件边界，不能用字符串前缀（`D:/a` 与 `D:/abc` 不是包含关系）。保留用户选的父级库，避免切到子目录里的文档便缩小根。

不同根同时打开时显示细小的库色标，并在跨库场景提供紧凑库名提示；同名文件加最短可区分父路径，例如 `src / README.md`、`docs / README.md`。悬停显示完整文件路径和完整库根，标签列表始终显示二者。颜色从规范化库身份稳定分配，可重复，因此不作为唯一识别手段；无库显示中性色。第一版不引入可折叠彩色分组或库绑定规则，保持记事本定位。

## 状态与缓存拆分

当前 `AppState` 只有一份 `doc/path/revision/diskFingerprint/vaultRoot`，输入控件固定 ID `editor.input`，`lp::cachedPlan` 与恢复文件也按单文档设计。只画卡片并换 `state.doc` 会串撤销、滚动、附件目录和恢复数据，不能作为完整实现。

| 所属 | 保存内容 |
| --- | --- |
| 应用 | 主题、字体、字号、缩放、动画、菜单、设置、侧栏宽度、打开标签顺序、活动 TabId |
| 文档标签 | 正文及编码/BOM/换行、路径和文件身份、修改代次、磁盘指纹、语言/换行覆盖、恢复元数据、选区/光标/撤销/重做、滚动、折叠、查找状态 |
| 库上下文 | 根、展开项、筛选、选中项、树滚动、文件/大纲页签；附件目录由所属标签文档路径求出 |
| 活动视图缓存 | LP计划、装饰快照、富布局、大纲、查找命中；先允许切换时重建，以正确性与内存可控为第一步 |

使用稳定递增 `TabId`，UI ID 为 `editor.input.<TabId>`。同一物理文件通过规范化路径及必要文件身份激活已有标签，防止两个缓冲区覆盖同一文件；不同路径指向同一文件的别名需纳入 Windows 文件身份检查。未保存页按 ID 区分，名称可为“未保存 1”。移动状态时避免复制正文和撤销栈，不为每个后台页常驻完整 LP/富布局。控件关闭时必须从 StateStore 删除相应 ID，释放正文、合成态、撤销及布局；不能仅隐藏。

现有全局 LP cache 第一版只服务活动页，切页清缓存并根据标签正文重建。内存探索已在进行，暂不增加每个标签一套渲染计划。库扫描数据可按根共享，而展开/滚动按标签保存；只监听活动库。切库重置监听防抖代次，旧库通知不得应用到新库。后台标签外部文件变动在激活时核对指纹，保存前照常校验。

## 操作与数据保护

点击文件、最近文件、外部单实例请求：打开新标签或激活已有页；不因新开页提示放弃当前修改。Ctrl+N 新建，Ctrl+O 打开，Ctrl+W 关闭当前，Ctrl+Tab／Ctrl+Shift+Tab 切换，Ctrl+1…8 定位、Ctrl+9 最后一个。菜单清晰提供“关闭标签”和“退出”；第一版可用简单左右重排，拖拽可后置。最后一页关闭后建立干净空白页，保留窗口。

切页前结束或取消当前 IME 合成，合成状态不能带到另一文档。图片预览、重命名、风险操作及保存确认期间冻结切换；确认事务捕获目标 TabId/文件身份/代次，不能读一个随用户切换而变化的全局当前页。

关闭脏页沿用保存／不保存／取消。取消或另存取消保留原页及顺序；保存失败或冲突保留目标页并回到该页。退出逐页确认，只在全部允许后退出，任何取消停止剩余关闭，不丢失未询问页面。重命名/删除文件或文件夹影响全部命中标签的路径、指纹和恢复来源；删除后脏页保留为未保存文稿，不能仅保护活动页。

恢复机制必须从单一 `recovery.txt` 扩展为每个标签的独立恢复文件和原子 session 清单，清单保存标签顺序、路径、编码、库根及活动 ID。启动新文件请求不能清掉其他页恢复稿。第一版不声称提供完整会话恢复前，至少必须可靠恢复所有未保存页；只有脏页写正文恢复，干净页记录路径，切换不能复制/覆写其他页恢复文件。关闭已确认丢弃的页只清它自己的恢复文件。

## 分阶段落地及验收

1. 先拆 `DocumentSession` 与 `VaultContext`，在单标签状态下验证保存、冲突、IME、附件、撤销、重命名和恢复现有行为。
2. 实现稳定 TabId、会话管理、每页恢复、打开去重及关闭事务；模型检查覆盖不同库和多个脏页取消，不仅检查渲染卡片。
3. 接菜单同行圆角卡片、窄窗溢出、快捷键和侧栏上下文恢复；活动缓存按需重建。切页成本专项之后再优化。
4. 最终 EXE 实机验证：A/B库往返、同名文件及同文件重复打开；各页独立正文/撤销/选区/滚动/折叠；库外另存、附件；后台文件改动/移动/删除；多脏页退出保存失败/取消；恢复后外部请求；中文IME切页；主题、100%/150%及UI字号18、窄窗口；开关多页后记录私有提交是否回落/是否持续增长，绑定最终哈希并正常退出。

实施涉及 `state/app_state.h`、`state/app_actions.cpp`、新增 `state/document_tabs.cpp`／`model/session_storage.*`／`ui/tab_bar.h`、`app.cpp`、正文／侧栏及 `Ui::StateStore` 释放入口。后台页释放扫描与富布局，只保留编辑状态；目前不共享多库扫描结果。已实现列表内左右重排，拖拽排序后置；真实中文 IME 切页、多屏物理 DPI 与大量大文稿的长期内存验收仍待后续。
