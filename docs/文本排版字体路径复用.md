# 文本排版中的字体路径复用

样式文本的一次布局可能度量数千个片段。即使字形度量缓存命中，度量入口仍需先将字体族和字重解析为字体文件路径，才能查询以实际字体身份为键的缓存。粗体、等宽字体和自选文件的解析会检查候选文件；逐片段重复检查可能成为重排成本。

`TextPrimitive::FontResolutionScope` 为一次同步操作提供有界复用。`InputModel::rebuildLayoutFull` 在装饰表非空时启用它，覆盖该次全量重排中的片段度量；调用结束释放。布局未变的缓存读取、无装饰的纯文本和逐行增量更新沿用原路径。装饰表非空是行表判据，不保证每一行都含可见样式。

```cpp
{
    core::TextPrimitive::FontResolutionScope fonts;
    // Synchronous measurements within this operation reuse family/weight paths.
}
```

## 身份与失效

- 键为原始字体族字符串和字重，值仅为解析后的路径。它不缓存文本、断行、字形或光标数组；后续度量仍使用现有的路径、字号和文本缓存键，设备缩放仍参与原有度量。
- 同一作用域将文件系统视为稳定。下一次作用域从空表开始，因此字体导入、候选粗体文件新增/删除、缺失字体恢复以及候选目录变化会重新解析。需要观察操作中途的文件变化时，结束当前作用域后再测量。
- `setDefaultFontFiles` 通过现有共享文本缓存清空入口推进代次。每次作用域查询在现有递归锁内核对代次；另一线程切换默认字体或清空缓存后，后续查询丢弃旧路径。整次布局不持有共享锁。
- 作用域属于当前线程，嵌套作用域各有独立表，销毁时恢复父作用域；父作用域仍会核对代次。对象不可复制或移动，须按栈顺序结束，不能跨线程使用。
- 每个作用域最多保留32个键，累计条目结构及字符串长度的估算预算为16 KiB；超限的请求正常解析但不记录。预算不是进程内存上限，也不是分配器实占字节。
- `NEO_TEXT_CACHE_OFF=1` 时绕过这层复用，继续支持无缓存对照。

## 验证

正式门禁包含 `text_font_resolution_scope`，覆盖字体族/字重隔离、精确度量等价、嵌套和线程隔离、活跃作用域内切字体/清缓存、容量约束、文件状态在下一作用域变化、DPI及缓存关闭对照。现有 `text_metrics_cache` 和输入/Markdown回归继续检查字形缓存、UTF-8映射及布局行为。

性能验证须使用同一文档、字体、宽度轨迹和构建配置进行交错独立进程A/B，保留预热与负例，逐步核对布局几何。组件CPU结果不直接代表实际拖动帧率、GPU开销或输入到屏幕时延；真实窗口与持续手势另行验收。
