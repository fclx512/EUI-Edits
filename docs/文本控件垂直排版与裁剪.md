# 文本控件垂直排版与裁剪

本文记录小型单行输入框出现文字顶部／底部被切、文字看起来偏上的排查与修复方法，适用于采用自绘字形、字体回退和嵌套裁剪容器的桌面 UI。

## 症状与根因

常见症状是输入框高度看起来足够，但中文占位提示、某些字体或特定缩放下文字贴边或被切。不要先认定是 UI 库的统一默认样式问题：应先沿具体控件检查文字图元的坐标、可视区和所有祖先裁剪框。

NeoEditor 的文件关联搜索框使用 `components::input`。控件把文字放进自己的 `textViewport`，该视口和输入框外层都开启了裁剪。旧的单行垂直位置按行盒 `(控件高 − 行高) / 2` 计算，再额外加 `0.15em` 的固定下移量；这个经验来自特定中文字体、字号与 125% 缩放。字体回退、字号取整、字形 hinting 和不同字体的 ascent/descent 会改变实际墨迹相对行盒的位置，因此偏移并不能保证所有字形完整落在视口内。

裁剪不是只看输入框外框。应检查文字图元、文本视口、控件根节点、滚动容器以及窗口可视范围组成的裁剪链；最终允许绘制的区域是这些区域的交集。文字位于标称行盒内，也不代表字形墨迹一定在行盒内。

## 坐标与字体度量

先明确每层坐标单位：控件通常按逻辑像素排版；渲染层可能按设备像素光栅化。DPI 与应用缩放合成后，设备字号大致为 `逻辑字号 × 有效缩放`。字体 hinting 会把设备字号和字形边缘吸附到像素网格，因此设备像素下的墨迹偏移再除以缩放，不一定与逻辑字号保持线性比例。

字体度量至少有三种不同含义：

- `em`/字号是设计尺寸，不是可见墨迹高度。
- 行高是布局行盒，通常由字号乘行高系数得出，用来安排行与光标导航。
- 墨迹范围是当前实际字形绘制像素的上、下边界；它会受字体、字符、回退字体、字重、字号和设备缩放影响。

因此，避免用 `fontSize * 常量` 猜字形应该下移多少。若渲染器能得到行内字形的 ink bounds，容器内的视觉居中应依据墨迹范围；若要维持 baseline 排版，应依据字体 ascent/descent，并确认使用的度量与光栅化字号处于同一坐标单位。不要混用逻辑像素的布局度量和设备像素的 bitmap 边界。

## NeoEditor 的修正方式

单行输入框保留 `1.2em` 行盒并将其在控件中居中；小输入框的文字图元改用 `VerticalAlign::Center`。该对齐在字形构建后，以实际可见 glyph 的 ink top/bottom 为中心，避免用一条固定 em 偏移修正所有字体。文本视口仍覆盖文字行盒，并由输入框根节点约束在控件内。

光标高度沿用字号估值，但单行光标改为在同一行盒中心对齐，IME 候选窗锚点也共用这个坐标。多行编辑继续按逐行布局和 baseline/行盒坐标绘制，不对整段文字做垂直居中。项目调整位置时，应同步检查文字、光标、IME 锚点、选择区和裁剪框。

## 建议的排查和验收

1. 从具体输入控件开始，记录其文字、行盒、viewport 和祖先容器的矩形；检查矩形是否处于同一逻辑／设备坐标系。
2. 用目标字体与中文、拉丁、带重音字符、emoji/回退字体分别观察墨迹边界。不要只用 `A` 或字号高度代替墨迹测量。
3. 在 100%、125%、150% 缩放下核对实际设备字号、裁剪交集、baseline 或墨迹中心，以及光标和 IME 锚点。
4. 同时检查空值占位提示、输入文字、焦点光标、选中、IME 合成和窄窗口；占位文字与输入文字必须复用一致的几何策略。
5. 对无法运行 GUI 的改动，至少保留组件几何模型或渲染层级检查，并明确标注尚未完成实机视觉验证。

固定像素偏移只适合已限定字体和 DPI 的特例。通用控件应以渲染器实际使用的字体度量或墨迹边界确定垂直位置，并用目标缩放和字体回退验证裁剪链。
